# M1.5 自主日记实施合同

版本：v0.4.0。基于 `676f614` 的 M0/M1 与记忆修复增量实现。默认 `diary_enabled=false`；自动分享不开放。

## 模块与执行

`DiaryRepository` 管理日记专属 SQL、来源快照、租约和提交；`DiaryService` 负责调度、模型生成、验证、主人查询、修订和删除。二者位于 `companion/diary.py`。`companion diary-worker` 是独立进程，有独立文件锁和数据库连接；聊天 Worker 的 FIFO、发送协议保持原有行为。所有模型等待都在 SQLite 写事务之外。

每天本地时间 02:00 后整理前一天，使用现有 `timezone`。补写范围为最近 `diary_catchup_days` 个自然日；夏令时按相邻本地午夜换算 UTC。每天只有一个任务，重复调度不会覆盖已完成、失败、删除或取消的结果。首版不提供自动重建或旧日记的递归引用。

任务状态为 `PENDING / RUNNING / RETRY_WAIT / COMMITTED / SKIPPED / FAILED / CANCELLED`。网络错误和结构化字段错误最多尝试 `diary_max_attempts` 次；伪造来源、无效引文、敏感内容或无依据经历直接失败。租约、开关、来源指纹和隐私版本必须在提交事务内再次通过检查。

## 事实、来源与写作

生成输入包含当日已接收、未删除的主人私聊，以及与这些消息关联、确实标记为 SENT 的日常回复；开启 M1 时，还可通过同会话的有效 episode 带入前三个自然日内最多三条原始事件，作为明确标注日期的跨天背景。未发送的回复、主动活动提示、日记查询/修订指令、网页和音视频都不会成为日记素材。每条输入最多使用 500 字摘录，按配置限制主人事件数；来源不足时不调用模型。

观察段采用可逐字核验的摘录，并由服务端标注“主人说”或“我回复”。这证明的是对话中发生过该陈述，不把用户的转述当作亲眼观察。模型可以自由选择材料、标题、暂时想法和待探索问题，也可以返回不保存；不赋予固定性格、兴趣或情绪。反思与问题明确标注为暂时判断，不进入 Memory 或 traits。

生成结构见 `contracts/diary.v1.schema.json`。来源编号必须来自提供的集合，引用必须逐字包含于对应摘录。事实段的文本必须等于其引文；标题及反思还有活动和敏感信息检查。这些规则不是完整的语义证明，真实叙事质量仍需抽检。

全部提供给模型的来源都会进入 `diary_evidence`，并保存原始 event_id；SENT 回复还关联 outbox_message_id。来源集合采用稳定序列化后 SHA-256。首版不把旧日记、Memory 或 episode 摘要正文直接作为输入；跨天回顾只复用 episode 的事件成员关系，读取有效原始事件，因此删除前一天来源也能直接失效次日日记。近期聊天模型上下文同样排除日记指令往返正文。未来如引用旧日记正文，仍需增加递归依赖及遗忘测试。

## 数据与迁移

迁移链为 `0002_m1 → 0003_memory_index → 0004_diary`，保留现有记忆向量索引。新增 `diary_runs`、`diary_entries`、`diary_evidence`、`diary_revisions`。每个 companion 身份、日期、时区最多一篇日记；修订更新版本并保存旧版本。

readiness 检查所需表和字段能力，不再仅比较一个 Alembic 版本字符串。迁移进入 wheel。旧配置不需要新增字段即可运行。含日记记录的数据库拒绝破坏性 downgrade；回滚应用前应导出并明确处理这些数据，不通过降级静默删除日记。

## 预算

`scenario=diary` 使用独立日预算，同时受统一月预算约束。`memory_extract` 和 `memory_review` 继续共享记忆预算，主动私聊仍使用活动预算。日记默认输出上限 700 Token，模型请求和预留估算使用同一数值。使用量未知时保留金额并标记 UNKNOWN；费率未知或预算不足时不发请求。

默认每日上限 50,000 微美元（$0.05）是限额，不是预期花费。模型的失败与重试可能实际收费，账本不会假装 exactly-once。

## 主人入口

- `今天写日记了吗`：最近日期的任务状态。
- `读日记` / `读日记 YYYY-MM-DD`：最近或指定日期的有效正文。
- `日记列表`：最近 7 篇有效日记。
- `修改日记 YYYY-MM-DD 新正文`：有界修订，标记为主人修订。
- `删除日记 YYYY-MM-DD`：删除正文与修订，并为日期建立防恢复的删除标记。
- `暂停写日记` / `恢复写日记`：控制运行时开关，不能绕过配置的硬禁用。

这些指令沿用 Bridge 的真实 QQ 身份核验、Core 的主人和私聊检查。模型生成本身从不调用发送 Outbox；只有主人明确请求查看时，才通过普通私聊回复路径返回日记。

HTTP `/internal/v1/diary` 系列接口要求独立 `COMPANION_DIARY_ADMIN_TOKEN`（至少 24 位，不能等于 Bridge token）。Bridge token 不能直接读取这些管理接口；Bridge 仍是受信任的入站事件传输方，应限制其网络访问与凭据权限。路径、结构和错误码见 OpenAPI。

## 遗忘闭包

复用唯一的 `ErasureLedger`：先追加日志并 fsync，再清理数据库。日记删除记录包含日期和时区，即使恢复的是生成前的备份，也不会重新生成已删除日期。正文、标题、历史修订和来源索引均清空。

忘记来源 Memory、删除原始事件或原文到期，会失效依赖该来源的整篇日记。原始事实遗忘会清空所有可能转述它的回复，因此引用这些回复的日记也一起失效；旧版无法证明来源完整的日记保守失效。只删除某一天日记时，按日期和时区清理该篇、其修订指令和读取回复；无日期的读取及列表回复保守清理。其他独立日期的正文、修订、普通回复和记忆保持有效。读取时也会检查证据到期，后台 Worker 暂停不影响此保障。

生成期间隐私版本变化、暂停或日期删除会取消任务，旧模型输出不能提交。日记阅读与出站入队之间同样检查隐私版本。恢复必须携带最新的独立遗忘日志，缺失、损坏、截断或身份不匹配时关闭恢复路径。

## 验证和启用

`tests/test_diary.py` 覆盖原合同 D-01 至 D-25：默认关闭、稀疏日跳过、来源与主体、未发送回复、无效模型输出、注入、重复调度、崩溃租约、有限重试、聊天并发、暂停/遗忘竞态、修订、备份恢复、鉴权、费用、迁移、DST 和完整来源删除。原 M0/M1 测试继续运行。

`scripts/verify_diary_live.py` 使用 21 个合成日期（含跨天回顾）、真实 DeepSeek 和真实 SQLite 流程，单轮总限额 $0.05，输出 `docs/live-diary-report.json`。它验证结构、来源闭包和指定场景；它不是“20 个真实匿名化日期经人工审核”的生产质量门禁。反思可能过度解读材料，仍应按原始来源检查。

启用仍需完成目标环境的 Core QQ/VPS 联调、20 个真实匿名化日期的主人审核、备份/遗忘日志复制与恢复。正式配置保持关闭；启用后先私人保存和主人读取，自动分享、QQ 空间、DSH、Android、原生通话和摄像头执行继续关闭。
