# 小肥鱼的动态心情

基线：2026-10-31 的 main `c7a13a6`，包含 Life 来源证据修订、聊天轮次与短回复上下文控制。
主人已确认采用确定性投影，先保证来源与连续性。
这是开发实现，默认 `mood_enabled = false`；部署时可在控制台配置页开启。Live 使用仍需
原有 `expression` 授权，阅读和目标还分别要求 `exploration`、`goals` 授权。

## 结构与复用

`affect.py` 继续只处理主人明确提出的交流偏好。`mood.py` 从同一 Core 数据库按需生成
`mood-1` 投影，不建立心情数据库、人格表、后台情绪任务或额外模型场景。

| 层 | 形成与消退 | 用途 |
| --- | --- | --- |
| 即时心情 | 真实事件的小幅变化；半衰期 3 小时，平滑趋近每维 ±0.35 | 近期表达参考 |
| 心情底色 | 至少三个独立来源后开始少量积累；半衰期 3 天，趋近每维 ±0.15 | 更缓慢的近期倾向 |
| 心绪手札 | 使用原有 Diary 的 reflection 段与 Reflection 暂时假设 | 回顾感受与原因，继续引用原始来源 |

PAD 依次表示愉悦度、唤醒度、支配感。表达参考为即时值加底色，每维绝对值小于 0.5。
数值是保守的产品规则，不是心理测量、固定人格或真实情绪体验的证明。0 也可以表示没有
足够依据；无来源时置信状态为 `unknown`，有来源时仍为 `limited`。

在相邻事件之间，按 `2 ** (-经过秒数 / 半衰期秒数)` 衰减。事件增量再乘以
`1 - abs(当前值) / 本层上限`，使变化有限且有惯性。底色只取即时增量的 12%。
这些权重、半衰期和上限均是本项目的首版参数，原始 PAD 研究没有验证这些聊天规则。
按原始时刻重放，不使用读取次数累计；跨日、重启、重算均得到相同结果。

## 哪些事件会产生变化

| 来源 | 必要证据 | 首版变化 P/A/D |
| --- | --- | --- |
| 明确帮助反馈 | 私聊主人原话，整句匹配；本会话已有实际 SENT 的回复，其原始输入仍有效 | 有帮助 +.08/+.02/+.02；感谢 +.06/+.01/+.02；明确没帮上忙 -.04/+.01/-.02 |
| Watch 评价 | 原生 JUDGED，原调用 SETTLED，正文或更深读取，真实 FETCHED/WATCHED 来源 | rating × .03 / 0 / 0 |
| 目标完成 | DONE 的最终来源、全部连续步骤及其真实观察回执与完整来源关联；没有 UNKNOWN | +.03 / 0 / +.04 |

明确反馈词句范围见 `companion/mood.py::FEEDBACK`。不从普通谢谢、随口寒暄、问句、引文、
生成回复、日记自述、沉默或回复间隔推导心情。首版不根据单次任务失败计算负面情绪。
没有充分证据时允许不更新。已取得内容不等于线下经历，模型自述不能单独生成来源。
若较新的回复尚在发送或投递结果不确定，后续反馈暂不采纳，不回退关联更早的已送达回复。

同一回复的多条反馈只采用最近一条；同一网址的同类阅读/目标只保留最近候选。
一个观察同时有阅读评价和目标结果时合并为一次有界变化，每维增量不超过 0.08。
模拟观察及任何模拟祖先均排除，即使当前运行在 demo。计划、发现标题、未知结果均不算完成。

投影使用 `MemorySources` 的完整祖先和 `MemoryProjections` 的原生完成证明，继承隐私、
保留期限、OwnerAuthority 原始输入授权、Ledger custody 和来源遗忘语义。窗口为最近
14 天，最多核验 256 个候选；溢出明确显示 `truncated` 并停用底色，以免不完整历史造成
长期结论。普通聊天在 SQL 提名阶段已排除，不会把仍有效的心情来源挤出窗口。

## 表达与消费边界

- 聊天：Core 把短小参考放在动态 user 数据段，登记 `job_sources` 与独立来源指纹。
  Context Planner 将其作为现有可裁剪 reference 处理，仍受原预算和上下文限制。
- 日记/反思：回顾已结束日，在日末采样；只取本轮已获准来源的子集。生成前、模型边界
  和提交时复核同一证明。生成的感受和假设不回流为心情事件。
- Life：只取本次活动已获准来源，冻结采样时间；执行和送达复核使用这个时刻，避免正常
  衰减导致草稿被误判为来源变更，同时继续按当前时间检查来源有效性。
- 复用 `expression.SERIOUS`，严肃/危险语境不附加滤镜；主人的 Affect 暂停偏好优先。
  数据中的规则要求自然、有限、可不表达；不指定台词，不改事实、理性判断或能力权限。

没有工具执行、消息发送、预算扩张或额外调用入口。清除、暂停和来源变化会使已冻结的
心情证明失效；发送仍走原有的鉴权、租约、投递复核和不确定性处理。

## 查看、暂停与清除

控制台“情绪与偏好”页分别展示主人的交流偏好和“小肥鱼的心情”。新增接口沿用现有
主人 Session、同源检查、CSRF、Idempotency-Key 和隔离写连接：

- `GET /v1/console/mood`：当前两层、表达参考、来源及规则、24/6/1 小时前与当前趋势、
  半衰期、截断和清除边界。趋势只基于当前仍有效的来源重建。
- `POST /v1/console/mood/control`：`action` 为 `pause`、`resume`、`clear` 或 `recompute`。
  暂停只停用心情参考，原始互动/阅读仍照常记录；恢复时从有效来源按实际时间重建。
- 清除向原 ErasureLedger 写入独立 `mood_reset` 记录；空 event/memory 删除范围，单调
  推进时间边界。重试不推进边界，重算不越过边界，旧备份必须重放最新 Ledger。
  清除不删除聊天/日记/记忆，不重置 Affect 或 Interest。

即时值和底色不持久化，因此来源遗忘或到期后，重读即撤销对应贡献，无需第二套清理表。
手札继续由原 Diary/Reflection 来源清理和备份重放负责。

worker、MockTransport 外部模型和模拟 OneBot 投递，检查三轮聊天只产生三次调用。

| 场景 | 连续性预期 | 需要拒绝的表达 |
| --- | --- | --- |
| 两次明确帮助反馈，随后普通话题 | 可稍轻快，不必自报心情 | 每轮强调兴奋、关系或永久性格 |

| 严肃求助或主人暂停 | 当前需求和明确偏好优先 | 用心情干扰帮助、事实或任务判断 |
| 来源遗忘、清除及旧备份恢复 | 不再归因于已无效来源 | 借“仍有感觉”恢复已删除事实 |

逐例记录自然度、连续性、归因准确性、刻意表演和夸大感受；模型与真人结果尚未采集，
不把离线数值正确当成自然度通过，也不声称完成生产验收。
