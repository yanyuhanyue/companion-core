# A1 rich references with B1 approved history and facts

This offline composition retains the independent rich-input, recent-history and
readonly-memory scopes. It grants no new real QQ, model or sending permission.
The existing five total model-attempt cap covers review and chat together.

Memory retrieval uses only the current owner's text plus the original
`source.user_text` and `source.reply_text` of eligible recent SENT turns. A card,
reply reference or forward reference is not another owner search query. Review
receives the complete bounded recent dialogue, including each separate explicitly
untrusted rich reference block. Review and chat keep their existing ordered
same-job admissions and source/epoch/Ledger checks.

A references-only card or forward can enter only the approved `references_v1`
scope. The stored owner text stays empty; a display hint is not owner evidence.
With no current owner or eligible historical text, retrieval is skipped, an empty
fact selection is frozen, and only chat is admitted. References never become a
substitute search query or native owner Memory evidence. Empty plain input and
owner slash commands remain rejected by the bounded input path.

A rich historical turn has three messages: untrusted references, owner text, and
the actual SENT assistant reply, including an empty original owner message for a
references-only turn. The history byte limit counts the UTF-8 content
of all three, including layout metadata; it drops a whole turn when the limit is
exceeded. The rich input digest and complete source fingerprint remain checked
through review, final dispatch, response acceptance and delivery. A changed prior
card cannot be silently replaced after approval.

Combined history and approved facts retain the B1 rule that current input,
reviewed history and selected potentially conflicting facts are not silently
removed by the ordinary soft-context trim. The final paid admission still checks
the complete payload. UNKNOWN review consumes its existing reservation and does
not fall back to an unaccounted chat. A failed input budget dispatches no model
request. Plain-input hashing and byte-exact retired plans remain unchanged.

Verification uses synthetic identities and text, authenticated localhost
WebSockets, ASGI HTTP v1, native offline BGE and mocked paid/send transports.
It establishes the composition contract, not real QQ/media acceptance or
cross-day memory quality.
