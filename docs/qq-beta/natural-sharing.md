# 自然分享与独立链接消息

主动分享 B 站或小黑盒内容、反馈主人已接受任务的结果时，Core 会把真实读取资料交给
当前聊天模型组织简短中文。模型决定开场和表达方式，QQ 消息不再拼接读取范围、UP 主、
字幕状态和内部错误码等字段。主题、标题、正文及可用字幕仍作为有来源的参考保留。
主动问候继续使用原有聊天模型；日记没有自动发送入口。

文字与原链接分别占一条 QQ 消息。原链接来自通过校验的来源，模型不选择新地址。
两条消息共用同一次生成结果和原有分段发送合同，依次确认送达；第一条失败、取消或
发送结果不明时，后续链接停止发送。任务反馈在整组消息确认送达后才标记为已反馈。

## 生成与来源

分享和任务通知复用原有 `jobs.kind=activity`、聊天模型计费、独立 Worker 和 Outbox。
每次最多生成一次措辞；没有可分享内容时模型可以放弃分享。已接受任务的结果必须反馈
真实完成或未完成的状态，不能用放弃分享代替。模型或费用结果不明时不发送替代文案。

Core 将生成任务绑定到实际观察或接受任务的主人消息及其结果。构建上下文、模型派发、
采用结果和发送时都会重新校验来源、哈希、保留期限及隐私状态。外部正文仍是不可信资料。
原有来源删除与恢复重放会清除相关派生任务和消息；撤销未来读取不抹掉此前合法历史。
任务的实际资料来源登记到 `job_sources`，同时保留派生事件关系；通知来源撤回时停止
发布，已发生的模型用量照实结算。必需任务反馈的租约带 `window_notice="commitment"`，
允许 Bridge 在主人私聊范围沿原 begin-send/send-check 合同核验活动来源。普通回复仍要求
已批准的主人输入；该标记本身不授予发送权限。

分享仍受免打扰、暂停、空闲时间和共同主动发送频率约束。主人已接受任务的反馈保持
原有责任，不因暂停自主活动而取消。费用、窗口次数、并发、未知结果和发送幂等继续
使用已有账本。分段的窗口应批准至少两段，并保持 Core 与 Bridge 的分段策略一致。

## B 站登录字幕

匿名字幕接口明确返回 `need_login_subtitle=true` 时，需要主人提供有效的登录授权。
原生 B 站 Reader 可直接使用显式的只读账号文件，不必切换到关键词搜索工具模式：

```powershell
python -m source_reader --source bilibili --account-file <private-grant.json> `
  --core-url <private-origin> --adapter-id <bilibili-id>
```

账号文件、Core 授权登记、截止及撤销规则见 [账号来源授权](../source-grants.md)。
Cookie 只留在隔离 Reader 中，只发送给允许的 B 站 API；字幕 CDN、Core 和聊天模型不接收
Cookie。登录不证明每个视频都有字幕，也不构成看过画面或音频的证据。

相关回归覆盖生成结果、来源变更、授权历史、费用、任务反馈及消息分段。
真实网关、账号字幕和 QQ 展示需要在对应部署中另行验收。
