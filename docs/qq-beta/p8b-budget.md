# P8-B paid-model gate (offline candidate)

Base: `a33d3cb77f348828b17e4bb48c621c53cfcdc017`. No paid provider, real key, QQ session, deployment, or private backup is exercised. Production readiness remains false. Existing P7/P8 reports remain historical observations.

`Settings.paid_model` defaults to null. Changing `mode` or supplying a key cannot authorize HTTP. A complete private approval must bind a fixed provider/model/HTTPS endpoint, USD rates and validity, timezone/region, owner approval evidence, provider-side project/account budget evidence, a sole-database account scope, a pinned local tokenizer, and the exact provider input rendering contract. Nonzero input/cache/output prices are required. Missing/zero template rates and unsupported input contracts are rejected. No tokenizer or model is downloaded.

The supported renderer is `chatml-v1`: all ordered system/user/assistant contents, role markers, generation prefix, tokenizer post-processing, and an explicitly approved structured-output suffix are included. Extra message fields/tools/multimodal content and tokenizer truncation/padding are rejected. Token counts come from that local tokenizer, not `token_upper_bound()` or the context soft limit. Its artifact hash is checked before reservation and again before HTTP. **The provider framing/rate/approval evidence hashes are operator-attested private references, not machine proof that a provider uses this tokenizer or hidden framing.** Admission is valid only after independent verification of that exact provider/model rendering, JSON-mode suffix, rates and region. No real provider rendering contract or price evidence is supplied in this phase; real paid use is BLOCKED. If remote framing cannot be proven, do not populate an approval. A provider template/tokenizer/model change requires a separately reviewed contract.

`budget.reserve` uses the existing `model_usage` accounting under `BEGIN IMMEDIATE`. Migration `0017_paid_model_gate` adds admission metadata and frozen approval-window hashes without rewriting historical usage columns. Every text scenario shares attempt/request/day/month/window amount and call limits, plus provider concurrency; its existing stricter scenario limits still apply. Reservations use uncached input prices and maximum output. A single logical chat job counts both recall review and chat; extraction batches, diary runs and reflection runs have stable logical IDs. Each attempt has an independent ID, upper cost, immutable rate snapshot, payload hash, lease and I/O-start fence. Ordinary chat does not acquire an extra model routing/review call.

A single-use payload capability reaches the storage-free `ModelClient` only through `budget.complete`. The seam rechecks approval, payload, input proof, lease and current time after lock acquisition/input proof/fsync and immediately before adapter invocation. Adapter redirects are disabled. Failed/missing/anomalous usage and abrupt exit retain the upper estimate; UNKNOWN never releases concurrency or gets a free retry. Impossible usage or changed rates stops new calls. Cache discounts apply only after valid returned usage. The operator-only `record_provider_discrepancy` records a statement discrepancy or currency uncertainty, retains the larger known/reserved amount and permanently stops admission pending reconciliation; it does not authorize or unblock anything. Software estimates cannot guarantee a provider's eventual charges, FX or discounts; the separate provider-side account/project cap is mandatory.

The append-only budget journal extends the existing accounting; it is not another queue, memory store or permission service. It contains IDs, hashes, amounts, and the durable I/O-start fence, never prompts, responses, credentials or private paths. Fsync precedes DB commit, so a crash can leave conservative orphan evidence; that blocks until independent reconciliation. A newer journal paired with an older DB, a newer DB paired with an older journal, a changed journal identity, missing journal, malformed chain, restored paid DB, or legacy unresolved usage without admission metadata blocks. A fresh window cannot erase existing charges or unresolved concurrency. Both the **latest independent budget journal** and existing separate **latest ErasureLedger** must survive recovery. Official restore of any paid-admission DB revokes paid execution; no automatic reset/clear operation is supplied. Operator review needs the provider statement and every ledger attempt before an explicitly approved resumption. Losing/rolling back both DB and independent journal cannot be detected locally; restoring them does not confer a fresh account allowance.

Concurrency is account-wide only under the attested single-database/unique-entry deployment. Multiple independent databases, credentials or gateways using the same provider account cannot be bounded by SQLite; that configuration remains BLOCKED until a unique gateway/account-level control exists. UNKNOWN slots do not expire with the process lease.

Media/vision/audio pricing/input contracts are not implemented in this text gate. Actual production HTTP media paths fail closed (also when Demo is selected); existing explicit Fake/MockTransport tests remain offline. Reader, M1, diary, autonomy and other feature defaults remain unchanged.

B0 findings: missing approval/input proof and missing chat daily/request/window/provider-concurrency semantics are reproduced P1 defects; the existing monthly reservation transaction is already serialized, so an original monthly oversubscription race is NOT_REPRODUCED. Red/green logs are retained privately under the task evidence directory. Additional independent review reproduced pre-I/O DB rollback replay, legacy unresolved admission omission and expiry during input proof; each is covered by a regression and conservative journal/deadline fencing.

Offline verification is recorded against the final candidate SHA in the PR and final execution manifest. These results do not constitute provider billing, real QQ, recovery or runtime acceptance. Rollback is code-only to the fixed base before any approved paid deployment. Once admissions exist, migration downgrade refuses; preserve usage, latest budget journal and ErasureLedger and use a compatible isolated environment instead of dropping the accounting tables or returning UNKNOWN to RESERVED.

Final recipient review also binds each frozen window/admission to a private per-window HMAC credential tag. Replacing a key during a request or between requests cannot reuse that window, even at the same endpoint. The actual ModelClient must share the Core Settings instance; a different adapter configuration cannot consume its admission. ModelAdmission is an internal single-use calling contract for trusted application code, not a sandbox against arbitrary in-process code that already holds a provider key. No credential or tag is published by this task.

Accounting custody is also immutable per admission: its private journal path and journal identity are captured separately from the mutable enabling approval. Disabling that approval, rotating its journal setting, or encountering a journal read/write fault cannot erase a known higher charge or invoice. The DB retains the known amount and UNKNOWN stop even when the independent journal is unavailable; a new call requires reconciliation. Journal entries bind usage state as well as amount and I/O fence, so rolling a settled UNKNOWN back to RESERVED is refused. Existing in-flight financial evidence can still be recorded after admission stops. A corrupted/lost DB together with a corrupted/lost independent journal requires provider reconciliation; this software does not replace the provider-side account cap.
