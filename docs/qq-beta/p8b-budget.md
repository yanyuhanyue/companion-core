# Text-model budget estimates and usage reconciliation

`Settings.paid_model` defaults to null; `PaidModelApproval.live_approved` defaults to false. A key or `mode=live` alone never authorizes provider I/O. Owner approval binds provider/model/HTTPS endpoint, explicit USD currency, configured rates and review deadline, approval interval, attempt/request/day/month/window amounts and call limits, concurrency and the existing independent budget journal. `approval_sha256` identifies owner approval; `rates_valid_until` is an operator configuration review deadline.

Configured rates price local reservations and returned usage. These are **cost estimates, not a provider invoice or a provable maximum charge**. Supplier signatures, exact tokenizer/framing evidence and account-cap proof are not development prerequisites. Other applications or credentials sharing an account are outside the local ledger's scope. Actual prices, fees, cache policies and invoices are checked when available. Unsupported currency is rejected; no FX conversion is invented.

`paid_budget.estimate_input_tokens` estimates UTF-8 text bytes / 3 with message and structured-output overhead, then applies `input_estimate_safety_percent` (default 125%). It accepts only ordered system/user/assistant text, downloads nothing and claims no exact remote framing. `max_input_tokens` limits this admission estimate; output reservation uses the requested `max_tokens` cap. General context byte limits are unchanged. The historical SQL column `model_admissions.input_bound` stores the estimate without migrating or rewriting historical amounts.

Reservations remain atomic in the existing usage/admission tables with frozen configured rates and local limits, payload and credential hashes, leases and durable I/O-start records. Every scenario shares paid limits; stricter scenario budgets still apply. Cache discounts require returned cache usage; an absent cache count gets no discount. Logical chat jobs include recall and chat without an extra routing call.

Valid returned input/output/cache usage is priced with frozen rates. Small underestimates, including actual priced amounts above the reservation but within local limits, settle normally. Safe audit records retain estimates, actual counts, deviations, reserved and usage-priced amounts and diagnostic codes, without prompts, replies, keys or account identifiers. Large input deviations are diagnosed using the configured ratio and minimum-token threshold; they do not by themselves stop calls or imply provider distrust.

Actual attempt/request/day/month/window or stricter scenario amount overruns, output-cap violations and returned missing/invalid usage stop new admissions. Known valid usage and its priced amount remain recorded after a stop; UNKNOWN retains at least the reservation and any larger known liability. A transport error/timeout without a response retains a separate UNKNOWN reservation and consumes its call and concurrency slot. Existing bounded retries require remaining limits; a one-slot live-text window therefore stops immediately. UNKNOWN does not expire with a lease or silently release liability when late evidence arrives.

Unusable reply text and error HTTP responses remain errors. Their explicitly returned usage is settled at the budget calling seam before the error propagates; subsequent caller cleanup cannot reduce a known charge. A successful HTTP response with missing or invalid usage stops new admissions even when its reply text is also invalid. Retryable error HTTP without usage, such as 429/503, retains the same bounded retry behavior as a transport failure.

`budget.usage_diagnostics(sqlite3.Connection)` returns read-only anonymous aggregates. Calibration uses SETTLED paid calls: estimated/actual input, actual output/cache counts, reserved/usage-priced amounts, deviations and distinct diagnosed calls. UNKNOWN token estimates are never displayed as actual usage. With no calibrated calls currency is null. The billing basis is always `configured_rates_not_invoice`.

Chat and video usage each use their own configured rates, frozen in the admission snapshot. A model change updates the corresponding configuration for new admissions; existing accounting retains its original snapshot. Missing or changed video rates during a request remain a blocking configuration change.

Every paid HTTP request receives a final transport check after user hooks, binding method, URL, Host, authorization and payload. Transfer-Encoding changes are rejected; the outgoing stream is sealed to the original approved bytes and Content-Length. The budget callback rechecks journal custody, persisted request state, credential/config snapshot and lease; live-text also checks job, scope and deadline. Each invocation copies hooks into a scoped client and borrows the caller's transport without closing it or mutating shared hooks. Model adapters own no accounting store or permission policy.

The existing append-only budget journal remains the only independent budget record. Fsync precedes DB commit. Missing/mismatched/rolled-back journals or databases, restored paid databases and unresolved legacy usage block. Approval removal, journal-path changes and journal faults cannot erase known larger charges; in-flight financial evidence can still be recorded after a stop. `record_provider_discrepancy` records invoice evidence or currency uncertainty without authorizing or clearing anything. No reset, clear or automatic UNKNOWN refund is supplied.

Recovery preserves the current database, latest budget journal and separate latest ErasureLedger. Migration 0017 and historical amounts are unchanged; downgrade with admissions remains prohibited. Losing or rolling back both database and journal requires reconciliation because it cannot be detected locally.

The local operator command `python -m companion reconcile-video-rates --request <private-json> --request-sha256 <sha256>` handles one historical defect: valid video usage was blocked because its frozen video rates were compared with unrelated chat rates. The request contains only `request_id`, `journal_id`, `expected_head_sha256`, `authorization_sha256`, `deployment_sha256` and `idempotency_key`. The operator preserves the reviewed deployment and authorization evidence identified by those hashes. The command requires the original frozen configuration, a stopped window, cancelled work, one exact independent block and matching original observed usage and NORMAL diagnostic. It rejects missing/conflicting evidence, invoice discrepancies, other unresolved responsibility, restored databases and cumulative accounts. Callers cannot supply an amount or replacement usage.

The command fsyncs a versioned `video_rate_correction` receipt before rebuilding the usage projection. It retains at least the old charged amount, reservation and frozen usage price; attempts, observed tokens, old UNKNOWN/blocked records and window STOP remain. Repeating the same request is idempotent, including recovery after fsync-before-commit failure; a conflicting request is rejected. A corrected conservative amount is excluded from pricing calibration. The receipt supplies neither a video result nor permission to retry or send. Subsequent reception requires the existing cancelled-input proof and native successor-window handoff. Once this record exists, budget-journal readers must support `video_rate_correction`; older code must not be used for reopening.

Validation uses synthetic MockTransport/ASGI usage. No real key, balance, account, host, provider call, QQ send or paid deployment is exercised. Real operation still requires explicit owner approval; QQ, memory, Reader and other permissions remain separate.
