# 按需动图视频理解

私人陪伴窗口可为主人当前发送的 GIF、WebP、APNG 动图配置独立的视频理解模型。
聊天和首帧观察仍使用原聊天模型；它按当前问题决定是否调用 `understand_video`。
模型、提供方、接口、价格和输出上限来自配置。工具参数只有待确认的问题，不能选择账号、
改模型、扩大来源或传入下载地址。当前入口是已认证的 QQ 原始图片；普通 QQ 视频消息和
B 站视频下载不在这个入口的范围内。

## 处理流程

Core 保留原始图片签名、哈希和短期加密原件。聊天模型先看到保持原比例的首帧及动图时长，
需要理解动作、互动、表情变化或动图含义时可调用一次工具。未调用时只形成静态观察，
不能声称已经看过动作。

调用后，Core 将完整合成后的动图按时间顺序编码为无声 H.264 MP4，最长边不超过 512，
以 25fps 表示原时长，误差不超过一帧。APNG 的独立海报不进入动画时间轴。
同批静态图片以原有受限图片格式一同交给视频模型；结果记录当前资料的对应顺序。
视频分析作为带来源的观察交给聊天模型，由聊天模型结合原有记忆和上下文回复。

转码与视频请求只在内存中生成，不另建原件库。原图的帧数、总解码像素、字节、签名、
隐私版本、租约和截止仍有效；视频派发前再次校验。远程视频 URL 不接受。

## 配置与计费

功能默认关闭。启用时在既有 `paid_model` 中增加 `video_input`，并通过私密配置或环境变量
`COMPANION_VIDEO_MODEL_KEY` 提供 `video_model_key`。配置类型为
`companion.video_input.VideoInputPolicy`，字段如下。

- `approval_sha256`：本次视频调用范围的批准证据哈希。
- `provider`、`model`、`endpoint`：提供方标识、模型名和 HTTPS Base URL。请求发送到
  `endpoint` 后的 `/chat/completions`，使用 OpenAI 兼容的内联 `video_url` MP4；
  同批静态图片使用 `image_url`。网关必须实际支持这些输入，文字聊天连通不等于视频连通。
- `input_rate`、`cached_input_rate`、`output_rate`：每百万 token 的微美元价格。
  例如一美元每百万 token 写为 `1000000`；这些是配置价格估算，不是供应商账单证明。
- `estimated_tokens_per_second`：视频每秒的本地规划估计；
  `estimated_tokens_per_image` 是同批静态图的规划估计，默认 `1024`。
- `max_output_tokens` 默认 `1000`，`timeout_seconds` 默认 `45`、最大 `60`；
  `max_seconds` 默认整批视频合计 `30` 秒，`max_bytes` 默认每段 `4000000` 字节。

既有 `paid_model.max_input_tokens`、`max_output_tokens` 和金额限制还要覆盖新路线的请求。
私人陪伴窗口的 `per_request_calls` 从 `3` 改为 `4`，为首帧观察、可选视频分析、
可选记忆筛选和最终聊天预留最多四次。未调用视频时不会产生该次调用。
图片与视频分析共用 `content.image_daily_micro_usd`，所有调用共用原有窗口次数、
总预算、并发和独立日志；用量分别记录实际提供方、模型和冻结价格。

当前视频路线要求 `owner_private_v1` 私人陪伴、当前主人图片授权和已知价格。
单一供应商的 `cumulative` 账号额度合同不允许混入另一提供方，配置这种组合时关闭调用。
更换模型、接口、密钥或价格须重新生成运行配置和窗口接续凭据；已有窗口会检测配置漂移。

## 失败与验收

STOP、隐私变化、租约或原件失效、请求篡改会在派发边界阻止新请求。
已开始且结果或用量不明的调用保留 UNKNOWN 和金额责任，不自动换模型重试，不生成回复。
Bridge 的图片上传等待覆盖首帧观察和视频分析两个阶段，Core 逐次执行原截止和来源检查。

`tests/test_video_understanding.py` 使用生成的动图、Mock 供应商、真实 API 生命周期和独立
Worker 验证转码、可配置模型、调用选择、混合图片、费用与失败边界。
真实接入还需用对应网关验证内联视频支持，并核对实际动作理解和 QQ 回复；
合成测试不证明供应商的视频能力或识别质量。
