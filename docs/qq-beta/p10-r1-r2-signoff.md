## 2. R1 完整非空一致性集合

每行使用相同小型记录：`object_ref / source_ref / destination_ref / approved_actions / cutoff_at / bytes / ciphertext_sha256 / verifier_receipt_ref`。
现在 approved_actions 为 UNAPPROVED，其余实际字段 null。可按实际数量复制行，不省略历史/轮换记录。

| object_ref | 必须保全的对象与对象专属证据 | 成功回执 |
|---|---|---|
| `core_consistent_backup` | Core 非空 SQLite 一致快照、schema、Outbox/admissions/UNKNOWN/窗口及来源归属；源 DB/WAL/SHM 状态、已提交 WAL 纳入方式、非空分类计数与截止点。禁止活动 DB 单文件盲拷 | 现有 backup API 形成的可解密快照；恢复 integrity/FK、分类计数/引用一致。计数公开仅匿名聚合，正文留私密 |
| `latest_erasure_ledger` | 最新 ledger_id、原生末 seq、末记录/file hash、截止点、独立 custody；最终停写时再次核对 | 验证身份/顺序、回放最新删除闭包；已忘事件/纠正后继/派生资料不复活，合法独立事实保留 |
| `all_budget_journals` | 所有仍关联 admission 的当前/历史/轮换 custody；逐个 journal_id、记录条数、末记录序位、链尾/file hash。Budget Journal 没有原生 seq，不伪造 | RESERVED/UNKNOWN、金额、窗口、并发、I/O fence 与 DB 对账；不删负债、不换库补额度，独立托管/密钥恢复可验证 |
| `window_journals_spool_epoch` | 所有相关 Window Journal 原生末 seq/链尾/file hash；Spool 一致快照、stable epoch、窗口/输入绑定与入件证据、发送 reservation、未确认项、实际剩余额度 | 旧副本/换 epoch/重启/重复输入不能重获次数；SENT/CANCELLED 不转待发，DELIVERY_UNCERTAIN 不自动重发 |
| `snowluma_data_volume` | 模板卷 `snowluma-data` 的实际私密引用、大小/密文 hash、权限/镜像；独立内容读取/停写/复制批准 | 全新隔离副本与获准源相符，技术上禁止 QQ 出站 |
| `snowluma_qq_config_volume` | 模板卷 `snowluma-qq-config` 同上，配置秘密/敏感会话与密钥 custody 仅引用；不能因部署批准推定可复制 | 固定配置与隔离回读一致，不输出秘密 |
| `snowluma_qq_data_volume` | 模板卷 `snowluma-qq-data` 同上，包含的私人 QQ/登录状态须明确批准，不把“登录卷”假设成另一个独立卷 | 解密恢复由获准操作者执行，不能自动登录/扫码/发送 |
| `original_services` | 原 1Panel/OpenResty/redroid 等实际服务/应用数据库逐项对象、定义/权限/依赖；只在另行批准范围内读取/停写/备份 | 各获准对象独立恢复证明及原服务基线/事后健康证据；未经批准对象不操作，不能声称整机已恢复 |
| `host_snapshot_if_approved` | 实例快照覆盖/排除项、供应商恢复入口、密钥、独立故障域、费用/停机上限；如不在 R1 范围须明确排除及其未覆盖风险 | 供应商实际恢复回执；能力未知就 BLOCKED，不把文件备份当整机快照 |

三卷名称来自 [固定 Compose 模板](../../deploy/compose.onebot-direct.yaml)；实际部署可能不同，须逐卷映射，不凭模板证明当前挂载。
R1 的范围必须明确完整集合与原服务/整机的批准或排除项；某行缺失不能默认为空或“未使用”。
Core restore 不会替代其他行的恢复。早期空库/合成测试、旧目标手机记录、仅列文件名或计算 hash 均不足以签收本轮非空恢复。

### 一致性截止、隔离与停止

1. 获准后核实所有写入者和实际源/目标。停止新输入与发送 → Bridge → Worker → API；其他写入者、SnowLuma 和原服务必须有各自停止范围。记录屏障、在途 I/O 与每项截止点，跨文件不声称天然原子。
2. 停止无法撤回已发 I/O。保留 UNKNOWN 全额负债与 DELIVERY_UNCERTAIN；若结算、遗忘或账单晚到使记录更新，重取相关末位置与一致性清单，不能丢弃新证据凑成旧快照。
3. 加密集合及密钥分别保管，独立故障域/密钥恢复须实际验证。源/在线卷保持不被覆盖；恢复只能进入另一个全新隔离目标/路径，先用网络/防火墙/容器规则技术性阻断 QQ、模型和其他业务出站，并保存隔离验证，不能只靠 enabled=false。
4. 固定兼容代码在未发布临时库迁移、核对并回放**最新** Ledger，再做完整性/预算/窗口/来源/会话验证，最后只发布到获准隔离目标。有付费 admission 时保留 `model_budget_restore_required=1`，恢复来源 grant/设备会话不能重新授予未来访问。
5. 身份/范围/epoch/摘要变化，账本缺失/顺序不明，出站或原服务异常，额度重置、自动重发、已忘内容复活，源/目标指向在线卷或费用/时长超限：停止新增动作，保存失败回执与最新集合。隔离/停止未确认不扩大执行。

**R1 回退入口**：停止并隔离新恢复目标、保全诊断及三类最新记录，继续保留原数据/原服务；若批准的停机需恢复原服务，按其单独固定入口执行并核对健康。
不能以旧 DB/journal、重置 epoch 或覆盖在线数据作为回退。R1 PASS 须覆盖批准集合每行，记录实际 RPO/RTO/异常、独立解密恢复及主人签收。
