# P13 后续：从离线候选进入有限真实体验

本页是后续顺序与验收要求，不是运行、部署、数据、费用、发送、备份或合并授权。
以最终 [P13 门禁](p13-gates.json) 和交付回执的准确候选、CI、迁移与构建身份为准。
历史 P11 的 6/6 手机确认不记为 P13；当前主机与最末 STOP 尚未新回读，状态仍为
`NOT_RECHECKED`。P13 真人输入、付费调用、手机签收、业务生命周期和日记样本均为 0，
真实自然日、手机时延、独立账单均为 null。两个发布开关继续为 false。

## 1. 审阅候选，单独批准合并与当前状态回读

先审独立 Draft PR、累计额度故障回归、原生迁移与组合候选结果；合并需新的明确决定。
合并后验证实际 main 的完整 CI，再固定部署候选与构建身份。CI 构建 image ID、注册表
不可变摘要和实际运行 image ID 各按其证据等级记录，不能互相代替。

当前状态回读另列准确目标、只读命令/对象、操作者、起止时间和私密回执位置。
获得新授权后才核对 owner/bot、唯一 Bridge、原服务、schema、protocol/privacy epoch、
最新 Ledger/Budget/完整 Window/Spool 及当前 STOP。源端未知、未决费用/发送或日志不连续
时停止扩大动作。任何恢复或部署还须按对象另批，不能从“可以回读”推导成“可以改服务”。

旧无归属目标不自动回填 reflection 来源；启用 Goals 前单独审查。部署累计合同后的
回退必须保全新责任记录，不能用旧二进制或旧快照丢掉 PAUSE、UNKNOWN 或原计数。

## 2. 一张原图的独立真实验收

按 [图片申请](https://github.com/yanyuhanyue/companion-core/blob/5c01eb8db84087a93c67ce11e52fcd12cbd97bd5/docs/qq-beta/p13-image-request.template.json) 新绑定实际账户/模型/CDN、固定候选与
恢复材料，建议仅一张非敏感原图、一个输入、同 Job 的 Vision+chat 两次模型尝试、
一条主人回复、约 10 分钟聊天窗口和 USD 0.01 本地配置金额上限；均为拟申请范围。
原窗口总尝试仍不超过五次，历史和事实范围关闭，不更换 Key/模型来绕过实际拒绝。

只有原图捕获/下载/有效 Observation、两阶段 usage、至少两个未在文字泄露的视觉
细节、手机一次可见与双端 STOP/完整账本齐全，才记录有限图片通过。
引用/转发正文尚未取得，保持原 coverage；供应商账单没有独立对账就保持未对账。

## 3. 一个真实事实的业务 M1 闭环

按 [记忆生命周期](https://github.com/yanyuhanyue/companion-core/blob/748896c8944a8ccdfa9a122199888294675dfbc5/docs/qq-beta/p13-memory-lifecycle.md) 与 [逐项申请](https://github.com/yanyuhanyue/companion-core/blob/748896c8944a8ccdfa9a122199888294675dfbc5/docs/qq-beta/p13-memory-request.template.json)
先批准准确非敏感主人事实与独立对照，聊天与发送保持停止。首次业务 B1 用获批原生
Memory 操作及真实来源完成签收；后续 QQ 控制 scope 仍每次只批准一条精确命令，
最多 15 分钟，不调用模型、不回复管理消息。不得用离线结果填写业务 B1 回执。

纠正后的只读 QQ 复问安排在遗忘之前；遗忘后的未知回答另开获批窗口。删除前加密
备份、新隔离恢复目标、最新 Ledger 回放、FTS/BGE 重建与对照保留各有独立回执。
无授权或来源/闭包不明确时不操作。P13 标签/一跳实验没有净收益，继续原生产检索；
后续先冻结真实匿名漏例与判分口径，再决定是否有必要改检索。

## 4. 一个真实自然日的 SHADOW 与私人日记

按 [自然日审阅](https://github.com/yanyuhanyue/companion-core/blob/24022ede7064d06002042fe0b10fdb498aa73b53/docs/qq-beta/p13-growth-day-review.template.json) 分别记录主人明确偏好、独立完成
阅读形成的兴趣、反思来源/否决、缺失段和人工评分。每项未测为 null，不从模型自述
补评分，不把同日重复读取、标题或模拟日期计成跨日成长。

按 [独立日记申请](https://github.com/yanyuhanyue/companion-core/blob/24022ede7064d06002042fe0b10fdb498aa73b53/docs/qq-beta/p13-private-diary-request.template.json) 选择已经真实结束的一天及
完整获批来源，独立日记预算、默认不分享，主人审核事实支持、遗漏和隐私内容。
下一真实自然日发生后再检查接续；修改、删除、旧备份不复活分别签收。Reader、表达
变化、主动分享与外部账号仍另批，不能因有目标或草稿而开放。PAD 维持只读研究。

## 5. 累计合同签收后逐步观察日常 Beta

累计功能必须先完成准确候选审查、负例与主人单独批准，再填写稳定匿名账户、Key
归属、币种/时区、完整旧责任导入、当前日志头和各维度最严上限。缺少旧发送原始时间
或完整链条不得猜测补齐。新窗口/续签只追加新批准，不清零历史、暂停或未知责任。
本地限额不约束同账户在其他程序中的费用，也不是供应商硬扣费上限。

按 [P13 运营与反馈](p13-beta-operations.md) 事前冻结真实第 1/3/7/14/30 天的观察目标和
升级门槛。API、Worker、任务、协议回执、手机可见、费用、独立账单与缺口分别记录。
仅有日期或无缺口采样不能证明端到端健康。QQ 登录卷/原服务/整机的恢复补足按
[原逐对象申请](p12-recovery-request.template.json) 另批，先技术隔离再打开恢复资料。

没有新的真人签收时保持 B1/B2/B3 与发布门禁未通过；无需虚构 30 天才开始一个获批的
有限窗口。许可证决定不在本轮 A–F 范围，后续由主人独立决定，不阻断已获准的私人测试。
