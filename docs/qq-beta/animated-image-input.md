# 主人私聊动图

已批准的 `owner_image_v1` 识图链路支持 GIF、动态 WebP 和 APNG（`image/png` 或
`image/apng`），也保留普通静态 PNG、JPEG、WebP。SnowLuma 顶层 `image` 段的
普通子类型 0 与动画表情子类型 11 使用同一来源校验；闪照、market-face 扩展及未知字段
仍不进入这条下载链路。文件名扩展名不决定格式。

Bridge 领取原租约后只向固定 QQ CDN 发起有界下载，签名覆盖实际原文件字节、MIME、
消息、窗口、来源与租约。Core 校验解码格式和资源限制，再从时间序列均匀抽取至多六帧，
包含首尾画面，拼为一张静态 PNG。模型输入注明原帧数、抽取帧号、时间及阅读顺序；
原生观察保留这项抽样说明，最终聊天继续使用同一份可重算拼图，不能声称看过完整动画。

每个动图仍计一个图片输入，在原 Vision 和聊天阶段分别使用已有估值与付费账本，
不增加模型调用。原文件摘要、上传签名与短期原文件存储继续绑定原始动图；
派发摘要绑定实际拼图及说明。派生图片和原始字节都不进入长期聊天历史。
完成、到期、停止或遗忘时沿用既有原文件清理与删除账本回放。

每份文件继续受原批准字节与像素上限约束，尺寸至多 4096；动画至多 240 帧、
总解码像素至多 6400 万。拼图每格最长边至多 512，并保持原批准的总像素、字节限制。
APNG 的独立封面不当作动画首帧；透明度、帧混合和 disposal 由 Pillow 解码器合成。
参见 [Pillow 动画格式说明](https://pillow.readthedocs.io/en/stable/handbook/image-file-formats.html#apng-sequences)。

合成回归通过真实 API lifespan、独立聊天 Worker、已认证本地 WS、原生账本与 Outbox，
仅 CDN、提供方及发送传输使用模拟。覆盖三个动画格式、来源摘要、抽样说明、帧顺序、
限制、格式混淆、语义气泡和后续普通消息。合成回归不等同于手机验收。
