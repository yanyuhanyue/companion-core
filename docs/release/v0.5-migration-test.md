## 样本与断言

| 检查 | 数据与实际断言 |
|---|---|
| 0003 → head | 主人身份、会话、事件、任务、事实、证据、修订、FTS、向量、Outbox、usage、运行元数据；逐表记录升级前全部旧列，升级后逐值比对 |
| 0004 → head | 除上述数据外，两天独立日记、运行、证据与修订；旧列及来源 ID 保持 |
| 索引/完整性 | FTS 实际匹配；合成向量字节与索引版本保留；`integrity_check=ok`、无 foreign_key_check 结果 |
| 重复升级 | 首次至 0013 后重复 `head` 和 `0013_content`，旧数据不变化 |
| 旧 0003 加密备份 | 验证密文不含原始 SQLite 头或样本文字；Fernet 解密确为数据库；在新路径恢复并升级 |
| 最新日志重放 | 备份后遗忘一个事实；恢复旧库配最新独立日志，目标正文/索引/证据/修订被清除，另一独立事实逐列保留 |
| 投递与费用 | 6 种 Outbox 状态及 3 种 usage 状态；恢复中待发送项转不确定，已有 SENDING 不重发；RESERVED 转 UNKNOWN，保留费用信息 |
| 旧 0004 日记恢复 | 备份后删除指定日期；恢复目标日记 DELETED、正文/修订/证据清空；另一日期及独立事实保持 |

`tests/test_release_privacy.py` 进一步覆盖两种 ISO 日期别名的读/修订副本删除、删除前后的加密快照、历史 COMPLETE 删除补清理，以及新观察依赖旧上游证据过期的读取/生成竞态。已有测试继续覆盖破坏性降级拒绝、日志缺失/身份不匹配/截断拒绝、隐私 epoch 和投递不确定性。

复现：

```powershell
./scripts/check.ps1 -TestFiles tests/test_release_migration.py,tests/test_release_privacy.py
```

脚本使用工作区 `.local/test-temp` 下的唯一临时目录并清理自身产物。所有输入都是合成数据；没有迁移或复制生产数据库。

## 隔离 Linux 恢复复验

候选 Core 镜像在目标开发 VPS 无网络容器中生成一条演示事件，制作加密备份，再追加独立删除记录，在全新路径恢复。要求 schema=0013_content、事件 redacted=1、完整性/外键检查通过。最终证据与镜像 ID 见门禁记录。这是开发恢复检查，不包含真实 QQ 服务、生产断电或异地备份服务验收。

## 回退与保护

本轮修复未改变 schema，因此部署回退仅涉及候选代码/镜像选择。不得为了回退代码执行有数据的破坏性降级。旧数据库恢复必须始终使用最新独立 ErasureLedger，并保留原数据库直到新路径的完整性、身份、投递未知状态和删除重放检查完成。不得以较旧的删除日志替换最新日志。

未验证：生产库规模、实际异地备份可达性、断电恢复时间与长期负载。G1 必须另行完成这些检查后才能判定生产就绪。
