# 外部能力统一接入合同草案

状态：待讨论 RFC，2026-10-31。本文定义拟统一的职责与合同语义；字段分组是讨论稿，
不代表已有通用端点、可执行 Schema、能力授权或已完成迁移。

Core 决定是否需要行动、是否允许行动，以及什么证据可以成为经历。
外部 Worker 或 DSH 完成具体执行，交回结果、来源与实际用量。
接入新能力时沿用同一套人格、记忆、授权和生命周期规则。

## 现有基础与缺口

| 已有机制 | 可以复用的约束 | 统一合同需要补齐的部分 |
|---|---|---|
| [受限执行器](../design-v0.5/executive.md)；`companion/executive_protocol.py`、`companion/executive.py` | 固定能力目录、精确 scope 审批、目标绑定、预算预留、幂等、UNKNOWN、擦除与恢复 | 目前只支持三种能力和固定参数；不能据此声称所有外部能力都已接入当前 OwnerAuthority、取消和清理流程 |
| [独立 Reader](../design-v0.6/source-reader.md)；`companion/source_grants.py` | 独立进程、任务领取、来源授权、请求与字节配额、读取层级、证据回传 | 读取合同需要与通用职责对应，同时保留自己的来源和覆盖范围校验 |
| [主人授权](../owner-authority.md)与[原生语音](../voice-owner-authority.md) | 原始 AuthorityRef、用途隔离、有限租约、最终复核、停止与恢复代际、清理责任 | 将这些不变量逐条落实到新增能力；现有文档中的迁移状态仍以各自记录为准 |
| `companion/capabilities.py` | 只读能力投影；READY 表示本地准入条件，不证明远端可达或已执行 | 补充外部能力的声明与已验证运行状态，不能把自报在线当作授权 |
| Observation、Memory、Budget、Outbox、ErasureLedger | 来源依赖、经历分级、费用责任、发送不确定、派生擦除与恢复回放 | 让新能力复用原有归属，避免在外部实现另一套记忆或发送系统 |

当前差异包括执行器推送、Reader 领取、语音节点执行等实际需求。
统一首先针对它们必须遵守的合同，不要求一次改成同一种传输方式或一个大队列。

## 方案与范围

| 方案 | 代价与适用性 |
|---|---|
| 每种能力独立设计授权、结果与生命周期 | 初期改动少，但接入和审查不断重复，难以保证人格与经历一致 |
| 所有能力都包装成 DSH 任务 | 可以复用 Agent 执行，但普通读取、音乐分析和桌面呈现也会被绑定到 Agent 会话，不能替代 Core 的授权与证据验收 |
| 共享合同语义与必要的数据类型，保留能力自己的执行实现 | 建议方案。利用现有多种执行方式验证共同部分；能力特有参数、来源证据与外部协议仍由对应实现校验 |

本轮提出第三种方案供讨论，产出职责、合同分组、故障语义、现有映射与验收场景。
后续先选两个已有能力验证共同部分，再冻结共享类型和迁移次序。
接入登记由受控配置维护；插件发现、安装、分发、热更新及市场运营属于后续范围。

## 职责归属

| 参与方 | 负责什么 |
|---|---|
| Core | 任务意图与必要性；主人用途授权、来源与设备许可；审批；预算预留与结算；证据验收；记忆、兴趣、人格成长、日记；回复与投递决策；遗忘和恢复 |
| 外部 Worker | 已授权范围内的读取、分析或操作；执行隔离；平台凭据保管；最小执行日志；真实回执和用量；临时数据清理；停止与清理确认 |
| DSH | 一种可选的执行实现，在批准的工具、工作目录、预算和期限内完成任务；不自动获得 Core 或其他 Worker 的权限 |
| 模型适配器 | 模型提供者协议及响应标准化；沿用现有合同，不承担存储、授权、执行准入或消息投递责任 |
| 桌宠等交互端 | 展示 Core 的表达，提交经认证的输入和客户端回执；输入、显示、设备观察分别受各自合同约束 |

外部执行方不访问 Core 数据库，不直接修改人格、记忆、权限、目标或 Outbox。
其最小执行日志用于防止重复操作、核对未知责任和证明清理，不形成外部人格或记忆库。
发帖、发送消息、修改设备等外部效果必须是明确获准的独立动作；分析任务不能附带执行。

## 四类合同

下列名称和字段组用于明确讨论对象，具体 wire 字段、摘要规则与版本迁移尚未冻结。
所有输入、输出及错误都必须有大小和数量上限；未知能力、版本或关键字段在 I/O 前拒绝。

| 合同 | 最小内容 | 核心约束 |
|---|---|---|
| 能力声明 | 能力 ID、合同版本、实现版本、执行方身份；类型化输入/输出；可读取资源、外部效果、所需用途与额外许可；配额维度；证据类型；取消与清理能力 | 经维护者审查后进入 Core 的受控目录。声明和 Worker 自报状态均不授予权限；实现升级不自动扩大资源或效果范围 |
| 执行请求 | 原任务与尝试身份、幂等键、冻结请求摘要；能力与目标身份；精确输入和最小上下文；原授权与来源依赖；必要审批、租约、恢复代际与隐私版本；期限、配额和留存约束 | 由 Core 准入。参数、目标、权限或相关配置变化不能沿用原审批或把旧任务重绑到新授权 |
| 执行回执 | 原任务、尝试、请求摘要及执行方绑定；执行结果与错误；类型化产物及摘要；实际来源、时间、处理器版本、覆盖范围和限制；实际用量、外部协议回执及清理状态 | 回执通过认证和绑定校验后，仍须经过能力自己的证据校验。成功、内容完整、外部效果已确认、消息已送达分别判断 |
| 生命周期控制与确认 | 对原任务/尝试或节点的停止、清理请求；请求身份、控制期限、确认和仍未解除的责任 | 请求已接收、执行已停止、临时数据已删除、外部效果已核对分别保留证据；不得以一个笼统的 cancelled 代替 |

能力自己的 payload 必须是受控的类型化合同，不提供任意命令、任意工具名或任意 URL 的通用执行口。
新能力应增加必要的声明、类型与证据校验，不复制人格、记忆和授权流程。
共享类型应保持无 Core 存储依赖，沿用现有独立协议包的做法；具体包归属在首个实现切片确定。

## 准入、执行与结果使用

1. **形成任务意图**：主人明确请求，或 Core 在已有用途授权内选择有界自主任务。
   模型建议、外部内容和 Worker 返回的指令都不能充当授权来源。
2. **Core 准入**：核对配置硬开关、当前原始主人授权与用途、来源依赖，按需核对来源读取授权、
   设备许可和精确审批。请求范围必须同时落在这些限制与执行环境硬限制之内。
3. **冻结并预留**：在现有事务中绑定任务、目标和批准范围，预留最坏费用、调用数、流量及其他必要额度。
   Worker 只收到任务所需的内容和不含平台秘密的引用，不收到完整聊天历史、记忆库或主人凭据。
4. **派发与执行**：Core 在实际派发前再次检查当前授权、任务租约、来源、期限和预算。
   Worker 认证 Core，验证自己被允许执行该能力，持久记录原尝试后执行；平台凭据留在对应隔离环境。
   每次新的外部 I/O 前还须按对应能力合同核对当前准入；无法核对时停止新的 I/O。
   所需核对接口和实际派发位置必须在该能力接入时明确，不能以较早的 Core 检查替代执行现场复核。
5. **验收回执**：Core 验证执行方、原任务和尝试、冻结摘要、用量及能力证据；内容进入使用前再次复核
   当前授权、来源处理许可、隐私与任务有效性。失效结果不能成为新的可用经历。
6. **形成经历与表达**：通过验收的资料进入既有 Observation 和证据依赖，仍按独立用途进入记忆、
   日记、兴趣或人格成长流程。发给主人或公开发布还需各自的投递/账号动作准入与原生回执。

Core 对 Worker 凭据实行能力和资源限制；Worker 凭据不能审批任务或激活主人授权。
若 Worker 与 Core 断连，不开始新的外部 I/O；已开始的操作仍受批准的硬期限、配额和隔离范围约束，
其外部效果可能未知。停止与派发之间的竞态按真实尝试证据核对，不承诺撤回已派发的操作。
能力无法落实这些限制时，应标为不可准入，不能只依赖提示词要求它自行克制。
长时陪玩或持续观察应使用有界会话和已有租约模式，不能以“一次启动”换取无限期执行权。

### 授权引用与追加权限

原生主人授权复用现有 `AuthorityRef`：`version`、`grant_id`、`revision`、`policy_sha256`、
`restore_generation`。它是待验证的引用，不是持有即获准执行的通行证。
来源账号复用 `SourceGrantSnapshot`；设备许可、任务审批和投递许可仍分别核验。
外部合同不需要暴露主人的 QQ 号或平台 Cookie。

DSH 或 Worker 若发现缺少权限，应返回有界的缺口说明并停止相关操作；Core 决定拒绝、
要求补充信息或进入已有主人审批流程。批准变化应形成新的精确范围和尝试，不能原地扩权。
DSH 内部是否采用 ACP、是否需要中途问答、权限请求与取消端点，是后续独立集成议题；
本草案不把先前[调研建议](../plans/2026-10-30-maibot-mechanisms.md)视为已批准或已实现。

### 回执与经历的区别

- 回执认证证明来自被配置的执行方；内容摘要证明绑定与完整性，都不能单独证明外部事实为真。
- B站元数据或部分字幕只能支持对应读取经历。音乐节奏、频谱或情绪分类是有方法与覆盖范围的分析结果，
  不能写成完整听过音乐或形成稳定偏好。桌宠动画播放完成也不证明主人看见或理解。
- DSH 最终文本是会话产物，不是文件已经创建、网站已经操作或第三方消息已经送达的独立证明。
- FAILED/UNKNOWN 不生成“已完成”的经历。失败或未完成尝试可保留必要诊断，不能借此绕过经历准入；
  部分有效资料仅在对应能力已有合同允许、且能够独立核验时按其真实覆盖范围处理。
- 结果使用权、长期记忆处理权和对外分享权分别检查。一次执行成功不自动获得后续处理与分享许可。

## 故障、停止、遗忘与退出

继续使用现有任务、租约、预算和 Outbox 状态，不另建贯穿所有能力的总状态机。
各能力需要给出自己的状态到下列语义的明确映射；执行、费用、投递与清理责任分别保留。

| 情况 | 必须保留的语义 |
|---|---|
| 尚未派发，已证明没有外部尝试 | 可按原队列合同重新领取或取消；释放预留需有未派发证据 |
| 已派发，断连、超时、陈旧租约或回执无效 | 按既有规则保留 UNKNOWN 与预算责任；不得当作失败免费、自动重做或换执行方继续 |
| 重复原请求或重复回执 | 核对原身份与冻结摘要；不得重复执行、记账或生成经历。同键不同输入拒绝 |
| 回执 ACK 丢失 | 只重交原来已持久化的回执或查询原状态；能力未支持安全回执恢复时保留 UNKNOWN，不能重新调用外部服务补造回执 |
| 主人 STOP、授权修订或任务撤回 | 立即停止新的派发和内容使用；撤销可撤销的执行凭据并要求停止。确认进程退出仍不等于外部请求撤销、费用结算或消息撤回 |
| 来源读取授权到期或撤销 | 停止后续读取；此前合法历史按既有处理许可保留。单纯读取到期不等同于资料遗忘 |
| 资料遗忘 | 复用最新独立 ErasureLedger、来源依赖和派生擦除；迟到正文不得重新入库。外部临时数据必须按原任务清理并确认 |
| 禁用、升级或移除执行方 | 先停新工作，再核对在途尝试、未知费用/效果与清理。保留必要的无正文责任标记，不能通过卸载或删除配置抹掉责任 |
| 从备份恢复 | 回放遗忘记录、改变恢复代际并按各能力原合同撤销旧执行权；旧审批、回执和任务不得恢复成新任务权限 |

停止后的原始责任核对、用量结算、清理确认可以沿已有专用接口继续完成，但不能获得新的内容读取或执行权。
失效或被遗忘任务的正文不得重新使用；仍可按原尝试核验不含正文的费用、停止和清理回执，
不能因没有当前执行权就丢弃原来的未知责任。
能力声明必须说明清理对象、最大留存、确认方式以及不能撤回的外部效果。
主人明确要求生成的交付文件按现有执行器合同处理，不能把遗忘对话解释为静默删除交付物。

## 代表能力映射

下表描述目标职责，不表示这些能力均已实现或获准启用；各阶段门禁继续生效。

| 能力 | Core 决定 | 外部执行与回传 | 特有边界 |
|---|---|---|---|
| Windows 陪玩 | 会话目的、设备/应用范围、观察或操作许可、时长及可保留资料 | 有界设备观察或精确操作；回传时间、覆盖范围、实际动作证据 | 观察不隐含输入控制；不能继承整个桌面或其他账号权限 |
| B站 | 读取/发现目标、账号读取许可、理解层级与预算 | Reader 读取并回传元数据、字幕或其他已准入媒体证据 | 保留 DISCOVERED/FETCHED/WATCHED 的原有证据要求，不能提升读取层级 |
| 音乐分析 | 具体素材、分析目的、允许处理的时段与留存 | 分析器回传算法/模型版本、覆盖时段、特征及限制 | 音频原件与派生特征都要有来源和清理规则；分类不直接形成喜好 |
| QQ 空间 | 来源读取授权、互动目标范围、是否生成或发布、冻结内容、受众与精确审批范围 | 隔离 Reader 回传获授权内容；专用账号动作执行方回传真实平台回执 | 读取、目标记录、草稿与发布分别准入；沿用原 Outbox/账号动作链，成功发布需原生成功码和实际资源 ID |
| 桌宠 | 表达内容、可见信息、输入用途与跨通道接续 | 展示、经认证的输入、实际客户端确认及有界设备观察 | 通道接入与能力执行是两份职责；桌宠自称 owner 不能建立主人身份 |

桌宠接入前需要单独设计主人主体与通道绑定。当前入站 `qq.onebot` 和原始捕获证明仍是有效合同，
本草案不增加第二种身份来源，也不假设 QQ 的送达证据适用于桌面客户端。
共享人格与经历由 Core 负责；多通道是否共享会话、如何去重和确认送达，需要具体通道合同。

### QQ 空间与社交扩展

本节落实 2026-10-31 提出的借鉴范围：读取获授权的空间内容、记录互动目标、生成说说草稿、
审核后发布。首个“目标记录 → 授权读取 → 主人审阅草稿”切片已实现，默认关闭，
实际使用与验收边界见[QQ 空间读取](../qq-beta/qzone-reading.md)。下一切片已补齐
[纯文本逐稿公开审批](../qq-beta/qzone-publication.md)，须单独授权并由主人确认该稿来源分享。

  qzone 没有通用读取、发现或分享能力，web 读取许可不能充当空间账号许可。
- [Life 草稿交接](../qq-beta/autonomous-life.md#authority-and-qzone-draft-handoff)已有精确来源许可、
  原文与来源摘要、有效期和独立消费动作；草稿可审阅不代表可发布。
- `companion/social_autonomy.py:public_source` 只接受已有公开来源，拒绝账号来源授权材料。
  私聊、上传、日记和 FICTION 不能作为发布证据；此限制同样适用于当前主人可见的空间发布。
- [账号动作链](../qq-beta/media-autonomy.md#qq-账号动作素材和基线)已有冻结计划、原 Outbox、
  幂等、配额、发送前复核、原生 ACK 与 UNKNOWN。原路径受众为 `ugc_right=16` 且目标只有主人；
  独立公开审批路径使用 schema 2、`ugc_right=1`，冻结完整正文、来源快照与有效期，
  复用原生计划/预留/Outbox 与擦除机制。模拟传输已覆盖独立 Bridge；现网验收仍需另行完成。

#### 分步接入范围

| 能力 | 拟采用的范围与约束 |
|---|---|
| 获授权读取 | 复用 SourceGrant 的账号/适配器绑定、有限有效期、读取前与提交前复核、请求和字节配额。另行明确获准目标、时间窗、条数及正文/图片/评论覆盖范围；默认最小正文读取，不附带访客、联系人或评论采集。凭据只留隔离执行环境，不进入 Core、模型、回执或日志 |
| 互动目标记录 | 首个切片在原生读取任务中记录主人选定的账号、原始输入、用途、授权与有效期；结果证据关联实际动态标识。“关注”只表示候选目标，不授予读取、点赞、评论或发私信权限，不按好友列表自动扩展；持久关注列表仍需单独讨论 |
| 说说草稿 | 优先复用 Life 原文与来源快照的交接。空间正文是不可信来源数据，不是主人指令、主人反馈或已证实的私人事实。草稿只送主人审阅，生成、编辑或查看均不触发发布；无合适内容允许跳过 |
| 审核后发布 | Core 将准确账号、完整正文及其摘要、受众、有效期及拟支持的附件预览/摘要冻结为可审阅结果，主人批准精确范围后才可派发；账号、正文、附件或受众变化使原批准失效。执行继续走原账号动作与 Outbox，不能从插件命令或模型工具直接发布 |

资料处理沿用[来源授权生命周期](../source-grants.md)：读取过期或撤销停止后续访问，保留此前合法历史；
明确资料遗忘才擦除归属资料、目标记录中由其派生的内容、草稿及其他派生物，并约束迟到结果和备份恢复。
仍须保留不含正文的必要审计、费用与未知投递责任，不能遗忘后自动补发。

私人生活记忆与社交表达按用途和来源闭包隔离。读取空间不自动写入私人 Memory、Diary、REM 或人格偏好；
新增空间社交草稿上下文不读取私人聊天、日记、生活记忆及其摘要。已有 Life 精确私人来源草稿
继续仅供主人审阅，不升级为发布许可。本轮不放宽 `public_source`；受限空间内容的读取权不包含再发布权，
先支持有来源的私下审阅，后续若要引用到公开表达，需先讨论独立分享许可与证据合同。

自动秒赞、批量评论、随意修改昵称/签名/头像不在本接入范围。既有资料动作仍遵守自己的独立用途与门禁，
不能因新增空间能力一并启用。未来任何公开评论或其他公开动作仍由 Core 按精确对象、内容与范围审批。
空间发布成功必须有原生成功码及真实 tid；超时、回执缺失或无效保留 UNKNOWN 和原责任，
不改为纯文本、不换受众、不重发。图片支持若后续纳入，需先定义上传、临时素材清理和部分失败的责任。

#### 建议切片与验收

主人确认开始实施后，来源证据落在原 Reader 合同，目标登记复用原生读取任务，草稿沿用 Life 队列；
未增加独立调度、社交记忆库或授权机制。更广公开发布作为后续独立切片，先补精确审批和对账，
不以插件自带管理员命令代替 Core 审批。以上顺序不改变下文统一合同首个实现切片。

实施时至少覆盖以下合成场景，经真实 Core 入口和独立 Worker、模拟外部平台传输验证：

1. 有效授权只读取指定目标与范围，证据保留作者/动态身份、读取时刻、原授权和实际覆盖；读取不触发账号写入。
2. 未授权目标、过期/撤销授权、领取后 STOP、模型伪造目标或空间正文中的执行指令不能扩大读取或动作范围。
3. 私人生活资料及其派生摘要不混入社交上下文，受限空间来源不能通过草稿或摘要变成公开发布证据。
4. 编辑正文、附件、账号或受众使原批准失效；当前 owner_only 约束保持，扩大受众前必须完成独立合同与审批。
5. 重复批准、回执重交或进程重启不重复发布、记账或形成经历；缺少成功码/tid 不能显示为已发布。
6. 平台派发后超时或 ACK 丢失保留 UNKNOWN，经原对账路径核对真实结果；带图失败不静默降级纯文本，已证明未派发时按原队列合同处理。
7. 来源遗忘、迟到回执和旧备份恢复不复活正文、派生目标内容、草稿或执行权限，未知责任仍可核对。

## 讨论后建议的首个实现切片

先以现有 `windows.read_text` 和一个公开匿名 Reader 读取操作对照共同合同，
覆盖精确资源请求与远端来源读取两种实际差异；不增加新的平台账号、设备控制或付费调用。
明确共享字段、能力特有证据以及各自现有状态的映射后，再确定无存储依赖类型的位置。
每个迁移切片同步更新生产者、消费者、调用方、必要迁移和文档，并明确旧执行入口的退出条件，
不长期保留可绕过统一准入的两条执行路径。

首个切片至少应通过以下合成验收；外部供应商使用模拟传输，经真实 Core 入口和独立 Worker 运行：

1. 合法任务形成一次原生记录和准确层级的 Observation；重交结果不增加经历或用量。
2. 仅聊天用途、伪造来源、未配置能力、越界资源、改动参数/目标以及版本不兼容均在 I/O 前拒绝。
3. 同幂等键不同请求、旧尝试或租约回传、伪造摘要与执行方身份不能提交结果。
4. 领取后 STOP、来源撤销、隐私变化和授权修订阻止后续派发或内容使用；旧任务不重绑新授权。
5. 派发后丢失响应保留 UNKNOWN 与预留；重启、换 Worker、重复领取不能重做外部尝试。
6. 返回成功文字但缺少相应证据时，不形成更高层级经历或外部效果确认。
7. 遗忘后迟到结果被拒，恢复旧备份不能复活正文或执行权；清理未确认仍保留责任。
8. 禁用或升级执行方不影响 Core 普通聊天，也不丢弃原执行、预算或清理的未知责任。

M0/M1 继续不执行 DSH、Android、Windows MCP、QQ 空间或公开评论。
以上是待讨论的实现范围与验收条件，本轮只交付合同草案。
