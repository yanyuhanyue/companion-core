## 2. L0–L3 按需上下文合同

这里按用户目标定义四层；与原 #26 将 L3 用于后台批处理的命名不同。提取/日记/反思继续使用原批次与 worker，不归为每条聊天的 L3，也不新增模型路由器。

| 层 | 何时进入 | 允许载入与退出行为 |
| --- | --- | --- |
| L0 最近对话 | 有把握的当前寒暄/问题，不依赖历史 | 静态规则、完整当前输入、近期已发送对话。不能因未载长期资料就断言“没有记录” |
| L1 当前情景/接续点 | 明确当前任务、暂停位置、待确认承诺 | 已有任务/目标/承诺/反馈状态的派生快照；带来源、更新时间和“执行/通知”分栏；不推测过去发生过什么 |
| L2 长期相关记忆 | 明确回忆、间接沿用偏好、跨会话项目且本地候选可解释 | 现有 FTS+BGE 初始≤6，可信一跳新增≤2，总候选≤8，最终参考≤6；纠正后的有效事实优先 |
| L3 复杂歧义核对 | 冲突、多指代、候选不确定、时间歧义；需要历史但无法可靠核对 | 在现有预算合同下至多一次额外 relevance review；冲突双方与“待核对”同保留。预算/权限/索引不可用时说明未核实或请主人澄清，不能挑一个答案 |

加载层只选择资料，不改变权限。确定性规则采用窄的 L0 放行；未知且有候选的间接问题保守进入 L3。“还是老样子吗”“那杯照旧”“按惯例来”必须有单独回归，而不是不断加一条精确句式就声称语义已解决。引用/转发/网页文字与主人有效请求分段；仅引用里的“记得/执行”不能触发历史或工具权限，引用后主人明确追问仍应识别。

建议装配顺序：身份/来源/当前 epoch 校验 → 本地查询与分层 → 有界来源参考 → 按最老完整 turn 裁近期历史 → 原预算硬准入 → 原 ModelClient → 同 epoch/lease 校验 → 原 Outbox。静态规则、当前输入和关键冲突/纠正参考不得被静默删掉；若最低合法上下文已超过经验证硬界，拒绝本次调用或请主人缩短输入。候选数/字符数/历史槽数不是 tokens。上下文检索结果发布前再次核对来源版本、删除闭包和 epoch。

无需历史的 L0 不增加模型分类调用。L3 只提出一次核对，不自动扩成执行循环。缓存前缀可保持静态字节一致，但不得把外部文字提升成 system。缓存命中只记供应商真实 usage；本地缓存必须绑定 owner、epoch、grant 处理语义、内容版本与嵌入/索引版本，纠正/遗忘/撤销即失效，最终权限检查与预算预留仍执行。

## 3. 可信来源的一跳记忆

节点引用既有 memory/episode/observation 或真实任务结果，标签/边/摘要仅为可重建派生物；不新增事实主库。本阶段不冻结表名、不提交迁移。每个节点必须能回到精确证据 ID、owner/private 范围、source grant 语义与版本、内容版本、epoch、派生构建版本。

边也有独立证据依赖与关系类型。起步只允许“同一证据共同记录”等可验证关系；共享标签和时间邻近只增加候选相关性，不能自动推出偏好、因果、同一经历或授权。只扩初始种子的一跳，稳定排序和去重后截断；不能把新增邻居继续扩成二跳。冲突不得被相似度或边数投票消掉。

删除闭包覆盖源事件 → memory/向量/标签/边/摘要/接续与经历视图/缓存；纠正后的后继若仍依赖被删来源，也不能复活。写入或发布派生索引前执行 epoch/version fencing；旧备份必须先取得并重放最新独立 ErasureLedger，再重建派生索引，无法证明完整即阻断。原 grant 的 COMPLETE 归属歧义继续 fail closed。

当前 [SourceGrantService](../../companion/source_grants.py) 的 `revoke()` 仅写 `revoked_at` 并调用 `cancel_grant_reads`，返回 `history_erased=false`；`forget()` 才写 ErasureLedger 并删除历史闭包。撤销“未来读取”停止新 GET，但保留此前合法历史，`read_revoked` 不默认失效；另行明确 forget 才删除并在旧备份恢复中重放。未来若提出“撤销历史处理”须另定冻结/删除合同，不能当作当前接口已有能力。实验中 `processing_revoked` 只是保守阻断的合成提案标记，不是新产品枚举。两种语义不得压成一个 `active=false`；合成通过不证明真实 Ledger、并发事务或恢复流程正确。

## 4. 表达与 PAD 提案

近期继续使用已有 AffectEngine 的明确沟通反馈。新的 PAD 仅是后续实验提案：真实已验证事件触发有限增量，按时间向中性衰减，带事件 ID、版本、到期时间，缺证据为中性；不用每条消息额外调用模型。待评审参数可从每维 `[-1,1]`、单事件变化≤0.1、最长180分钟开始，但它们尚非配置或已实现算法。

PAD 只能影响句长、节奏或表达候选的有限排序；不得修改事实、证据置信度、冲突判断、权限、预算、消息次数、承诺、工具授权或分享范围。主人暂停表达、严重语境与明确偏好优先。来源删除/修订撤销对应表达贡献；普通聊天不续期。稳定兴趣/特质须满足既有跨天、多来源证据门槛，短期 PAD 不写长期特质，也不解释为用户心理诊断或 AI 真实情感。

准入回归：独立维度 TTL、不活动衰减、普通聊天不续期、删除撤销、旧备份重放、引用注入、严重语境、最新主人纠正、预算/权限/投递输出完全不变。没有这些逐项证据则仅保留提案。

## 5. 真实经历、接续点与承诺视图

从现有目标/任务/步骤、Observation 与 Outbox 派生“想做/尝试/完成/已通知”的展示；这些中文标签不是新产品状态机。想做必须有真实候选来源；尝试要有已派发记录；完成需要成功结果和对应证据；已通知只在 Outbox `SENT` 后成立。`UNKNOWN`、`DELIVERY_UNCERTAIN` 单列等待核对，不能自动重试或写成完成/已通知。

接续点显示任务 ID、最后已验证步骤、暂停原因、下一步建议、证据和有效期。恢复只对仍有效的原范围生成候选，重新检查来源/权限/预算和租约，不能通过“接着做”继承过期执行批准。主人承诺显示对象、范围、截止时间、触发条件、批准来源和通知状态；自主暂停不伪造承诺已取消，取消某项则沿已有机制处理。

日记和兴趣只能依据真实已验证经历。标题发现、文字抓取、部分媒体、模型想象、模拟梦境分别标注；模型自述不创建真实经历。派生视图没有独立写事实 API；来源删除与旧备份重放后重算，送达不确定不能当作已告知事实进入对话。

## 6. 多模态与工具阶段

每项按“离线合同 → 合成故障/恢复 → 独立批准的有限真实验收”推进；已有实现不等于当前启用。模型适配器只处理协议，不持有存储、授权、预算或消息投递职责。共用调度/预算/Outbox 合同，不为每个模态再造长期记忆与工作状态机。

| 顺序 | 范围 | 最小可交付与关键限制 |
| --- | --- | --- |
| 近期 | QQ 引用/转发/图片理解 | 保留原作者、原消息引用与内容哈希；混合正文不能变指令；图片失败不能用标题冒充看图；引用链/转发深度与总字节有界 |
| 近期 | 表情库与语音条 | 主人允许的表情来源、版权/标签/检索与禁用；STT/TTS 明确供应商、音色、费用/时长/字节、授权与转录不确定；原媒体默认 discard；不得重复发条或自动外发 |
| 中期 | 生图 Provider / ComfyUI BYOK | 通用生图适配器与自托管 ComfyUI 分开协议；主人提供 endpoint/密钥/工作流白名单、费用/并发/超时/输出字节；仅批准的固定 workflow，不接受模型任意节点、脚本、路径或模型下载。超时后已有任务可能仍执行，保留 UNKNOWN 并核账，不盲重提 |
| 中期 | B站/小黑盒深读 | 复用 Reader grant、每次 GET 前及提交前复核、SSRF/资源界限；先有界正文/字幕，再明确覆盖片段的图像/音视频。标题/封面不是看完；无字幕/登录/反爬失败如实报告，不自动转为手机抓取 |
| 中期 | Android 只读与后续导航 | 先绑定设备/包/会话的显式屏幕文字观察；导航/点击是独立能力与批准范围，不能从只读升级；系统通知、账号、编辑框与其他 App 默认拒绝，离开允许包立即丢弃结果 |
| 中期 | Tailscale Windows 网关 | 现有受限文本能力保持原边界；随后逐项评审截图、键鼠、应用启动。每项需设备/会话/精确动作/期限及停止回执；断网/超时为不确定，不自动切云端高权限工具；文件探针不能代替桌面成对 E2E |
| 后期 | 唱歌、视频理解、游戏 | 分别验证音色/作品授权、媒体覆盖与时间段、游戏平台与账号/操作范围；游戏行动/购买和公开互动需独立授权；不把模拟体验当玩过/唱过/看完 |
| 后期 | QQ 空间、微信社交、电话 | 读取、草稿、公开发布、评论、私信、联系人、录音和呼叫分开授权；公开写与呼叫不是常规聊天权限。先准备可审阅结果，再执行获批范围，保留取消/未知与真实送达证据 |

证据术语必须能回答“到底做过什么”：

| 表述等级 | 支持证据 | 禁止推断 |
| --- | --- | --- |
| DISCOVERED | 标题、链接/封面被发现 | 已读正文、看过视频 |
| FETCHED | 实际获取的文字/转写/图像分析及处理器/来源 | 完整观看、设备执行成功 |
| WATCHED | 真实媒体分析、处理器版本、时间段与完整覆盖证据 | 片段代表整段、标题代表观看 |
| EXECUTED（未来展示术语） | 受控执行器真实回执、批准范围/任务 ID、可核验效果 | SDK 返回文字即外部效果完成 |
| DELIVERED（未来展示术语） | 原 Outbox/通道可验证的成功回执 | 请求已排队/发送不确定即已通知 |

现有 Observation 合同只按其支持等级入库；EXECUTED/DELIVERED 在本提案中是跨表派生展示语义，不能直接作为未定义的新枚举写进现有接口。

## 7. 历史漏例与下一轮证据

原 #26 [冻结读数](https://github.com/yanyuhanyue/companion-core/blob/1346fa29cb1f63651377dc33525a09fc96cd526a/docs/qq-beta/p8b-context-benchmark-results.md) 保留：baseline 与 experiment 必要参考都是7/8；baseline `pressure` 丢 `tea`，experiment `indirect` 丢 `tea`。前者是参考先被 soft 裁剪，后者是简单关键词规则将“饮料还是老样子吗？”判为 L0。review9→2为 stub 调用读数；gold/oracle 选择和 fixture candidate 不能证明真实语义、成本或速度。

本轮 [v2 合成合同实验](../experiments/p8b1-context-v2/README.md) 不改原样本/脚本/结果。保留原 fixture 快照哈希与历史失败，比较旧规则回放和新合同模型；补间接改写、歧义、接续、混合引用、同标签误扩展、有效二跳拒绝、最后装配前遗忘/epoch改变、未来读取撤销与历史处理撤销、恢复未重放 Ledger 等正负例。新结果只说明这些资料装配合同；不运行 Core、FTS、BGE、真实模型、QQ 或真实 Ledger。

下一轮先用固定公开合成集做检索臂：现有 FTS、FTS+BGE、FTS+BGE+有据一跳；采用100/1,000/10,000条相同目录，冻结索引/模型 revision、候选上限与查询。分组包含无记忆寒暄、直接/间接跨会话回忆、纠正/冲突/时间变化、无记录、引用/转发、遗忘/撤销。标注者与路由输入分离，独立保留未参与调参的查询；公开合成与随后获准的匿名真实样本分栏。模型缓存缺失则 embedding 臂 BLOCKED，不下载或用假向量冒充。

质量先于成本：每组 recall@6/precision、必要参考保持、冲突双方保留、纠正优先、无记录澄清、来源可追踪，逐项对照同样本；遗忘泄漏/越权/假经历/不确定投递冒充成功必须为0。任何重要分组退化先保留失败并关闭实验。小样本/规则拟合通过不进入生产。

获准真实 provider 以后才测全链路 `chat / memory_review / relation_review / memory_extract / diary / reflection / activity`，同时记逻辑 request、尝试、重试/压缩、批次/来源与预算 journal；UNKNOWN 保留非零预留且核账，不能算免费。以供应商真实 usage 的 input/output/cache-hit 和已验证 tokenizer/framing 对照，费率、币种、费率版本、费用估计与账单实付分别记录；缺失值继续 `null`。同样本配对A/B、随机/交错顺序、冷启动与热缓存分层，不能用字符或候选条数当 tokens。

真实模型/手机 E2E 仅在同匿名 trace 的实测样本记录 n、p50、p95、计时边界和误差；p50 用中位数，p95 用 nearest-rank `ceil(.95*n)`，n=0时均null。CPU/RSS/索引大小与冷模型加载单独测，不拿本地 stub 延迟当提供者或手机体验。所有本轮实际 usage/cache/cost/p50/p95 均为 `null`；不提出生产节省百分比。
