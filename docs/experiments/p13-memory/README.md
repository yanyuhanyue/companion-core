# P13-F2：标签与有据一跳的离线候选对照

本轮结论是保留原 FTS5+BGE 检索：新增标签/一跳没有提高必要记忆召回，增加了 6 条无关候选。生产检索、Memory 权威库和 API 均未修改。这里的通过仅表示公开合成实验及删除边界完成，不能用于声称业务 M1、真人回忆质量或图增强已验收。

## 固定输入与方法

源码基线 `eb5143500bed5395bb45f2a2cc20335da9988491`。先在 `df617a5b4dede29fcf1884717f5cc2a997a0960d` 冻结 [候选算法](../../../scripts/p13_memory_research.py) 和 [事实集](corpus.json)，随后在 `6daffcb359cf6afb03065ab05b3ba36b3e3d2dd7` 冻结新的 [15 条查询](queries.json)、[评分标签](gold.json) 和 [运行器](../../../scripts/evaluate_p13_memory.py)。运行器在三个方法完成全部候选检索后才加载评分标签；结果出来后没有按分数改算法或选题。原 P12 输入与结果 hash 也在运行前检查，其 **6/7** 留出结果及“休息日早上去哪锻炼”漏例保持原样；P8 **7/8** 完整上下文读数没有重跑或混入本表。

所有方法使用同一原生 Memory/SQLite 事实和证据：16 条主题事实加 40 条干扰事实，共 56 条；同一当前 `CONFIRMED`、无需复核、`user/project`、有效主人私聊来源池，查询前后校验 privacy epoch 与最新 Ledger。候选总上限均为 6。BGE 使用项目原 pinned 本地缓存 `BAAI/bge-small-zh-v1.5@46fbe35fd4374a00fee7de77dfddaeb6dd6a2c59`，原 `semantic_min_score=0.5`，无下载、模型 HTTP 或私人数据库访问。

| 方法 | 实际定义 |
| --- | --- |
| FTS5 | 原检索的 lexical 分支：原 trigram/ASCII 查询构造、BM25；不经过 BGE 过滤与融合，相同候选池与上限 |
| FTS5+BGE | 未修改的 `Memory.search`，只限制为共同合格事实 ID 和 6 项 |
| 有界标签/一跳 | 以上原生结果，加最多 2 项；NFKC/casefold 及 ASCII 单词边界的显式别名匹配，再走至多一跳 |

别名是**合成数据的人工标注**，不是自动语义证明：必须仍有准确 owner 原文、hash、逐字引文和 canonical/alias 字面值，主体一致。关联边还要求同一当前 owner 来源逐字包含两个事实；仅同标签不能成边，新增邻居不能作为下一跳根。来源更改、到期、遗忘或未回放 Ledger 时派生项失效。候选扩展只提名现有事实，不创建/确认事实、证据或权限，也不持久化图。

这是一轮同一作者准备的合成留出评测，并非独立人员盲评或真实匿名聊天集。冻结先后和评分隔离降低直接迎合答案的风险，不能消除题材选择、人工别名和 gold 定义的偏差。

## 实际结果

完整逐条候选、误报、来源摘要和运行输入 hash 见 [results.json](results.json)。13 项必要记忆分布于 15 条查询；`allowed` 可包含回答所需的支持事实，因此“候选正确数”不必等于“必要记忆数”。误报在每条查询内按唯一候选计数，跨查询重复仍分别计入。

| 方法 | 必要记忆找回 | 漏忆 | 返回候选 | 无关候选 | 候选 precision | 候选 UTF-8 字节 | 平均热态本地检索 ms |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| FTS5 | 4/13 | 9 | 11 | 5 | 54.55% | 463 | 10.41 |
| FTS5+BGE | 13/13 | 0 | 31 | 15 | 51.61% | 1367 | 25.56 |
| 有界标签/一跳 | 13/13 | 0 | 37 | 21 | 43.24% | 1642 | 26.52 |

相对原 FTS5+BGE，增强方案没有召回增益，多出 6 条无关候选和 275 字节（约 20.1%）。两个 `RQ` 问题各引入两条不需要的日期事实；雨天活动查询里，原生误召回的储物事实又扩出一条钥匙信息；钥匙查询则因误召回的器材信息再扩出雨天活动。来源有效并不等于对当前问题有用。原路径本身也在日期区分和盒子相关问题中产生误报，13/13 不代表回答完全正确。

这些是单轮、预热向量缓存后的本地候选读取时长，不是冷启动、吞吐、模型推理或手机往返基准。字节数不是 tokenizer Token 数。实际模型 Tokens、实际费用、真人评分、手机签收、业务事实和自然日样本均为 `null`，模型 HTTP 尝试为 0。

## 纠正、遗忘和旧备份

同一运行实际通过原 `Memory.decide` 将合成午餐事实由南瓜饭纠正为番茄饭。三个方法均召回新值，旧版本命中为 0。随后实际创建删除前加密备份，删除 `RQ` 别名/步骤的原来源以及午餐的完整修订族，恢复到新的隔离临时数据库，并先应用最新独立 Ledger，再重建 FTS/BGE。

当前库和旧备份恢复库中，三个方法的被删 ID/内容命中均为 0，被删向量行均为 0，保留在实验输入中的旧别名因来源无效而不可用；另一独立来源的橙色装订线事实仍存在且被三个方法召回。原事实与控制事实的来源/修订闭包独立。这是本地合成恢复，不是业务备份复制或真实 QQ 登录/主机恢复。

[边界回归](../../../tests/test_p13_memory_research.py) 另覆盖两跳禁止、同标签但不同来源/主体、无原文别名、来源改变/过期/删除、Ledger 已写而 DB 未应用，以及六项候选已满。生产的完整管理命令、删除和 custody 回归继续复用原测试。

## 按月只读视图的后续约束

现有 `GET /internal/v2/timeline` 仍仅支持 1–7 日、最多 40 项，保持 owner/self、模拟/实际来源和 Outbox 状态分别呈现。本轮没有扩大该端点。按月视图只保留设计：一次指定已批准时区中的一个自然月，按当前 `occurred_at` 分组，记录事件/修订来源、coverage、隐私 epoch、Ledger head 和截断标志；候选池有明确扫描上限，不把月份分组当作时间推理或新的事实。

月视图只能显示仍在原保留期和权限内的来源，不能因要显示整月而延长留存；缺日、来源已到期或部分读取必须保留缺口。缓存如以后确有必要，只能是可删除重建的派生索引，不能保存独立权威正文；每次查询重新验证原来源、主体、当前修订、epoch 和最新 Ledger，遗忘或恢复后先失效再重建。旧标签/旧月缓存不能重新注入已删事实。

下一步应在独立批准的真实漏例和匿名评审集上先冻结“正确/必要/允许/未知”的标注规则，分别测日期过滤、别名和一跳的净收益。当前结果不支持启用增强、扩大候选上限或增加图数据库。

## 复现与核验

在已有 pinned 本地模型缓存、锁定依赖的仓库环境下，设置 `HF_HUB_OFFLINE=1`，运行：

```powershell
.venv/Scripts/python.exe -B -m scripts.evaluate_p13_memory --embedding-cache .local/embedding-cache --output .local/p13-memory-reproduction.json
```

输出必须位于工作区；临时 DB、加密备份和恢复库仅创建于 `.local/test-temp`，退出后清理。复现会产生本机新计时，不应覆盖冻结报告来挑更好数字。最终相关 `scripts/check.ps1` 结果由 P13-B 生命周期页记录；各独立 Draft PR exact HEAD 的完整 CI 由集成报告另记。
