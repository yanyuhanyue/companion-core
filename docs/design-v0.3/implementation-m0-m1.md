# M0–M1 实施合同与验收门禁

## M0：一条消息只经过一个主对话引擎

**范围**：单 QQ 私聊所有者、NapCat/AstrBot 适配、Companion API 与 Worker、事件事务日志、去重、Outbox、DeepSeek Flash、Token 账本、基础隐私审计、配置校验、部署及故障恢复。

**不包括**：自动记忆提取、自主浏览、安卓 App、DSH 工作任务、QQ 空间、公开评论、群聊、声音、向量检索。

### 必须交付

- `astrbot_plugin_companion_bridge`: 只接管白名单 owner 私聊；能停止 AstrBot 默认 LLM 调用；非白名单拒绝；主动/被动消息统一经 Outbox。
- FastAPI API：OpenAPI 合同中的 M0 接口；API 不暴露公网，客户端附 Bearer Token 和幂等键。
- Worker：单会话有序领取 Job、模型调用、Outbox 事务、故障重试。
- SQLite：M0 表结构迁移、WAL、外键、唯一键和热备份恢复。
- Model Router：`deepseek-flash` 日常模型，支持替换 provider 实现；保存 token + 缓存命中 + 费用，费用统一以整数微美元记账。
- 监控：健康、排队数、故障率、QQ 发出回执、模型耗费；日志禁止出现明文凭证。
- 自动化测试：单测、合同测试、模拟 QQ 适配、模拟模型服务。

### M0 验收用例（全部 PASS 才允许 M1）

| ID | 操作 | 预期 |
|---|---|---|
| M0-01 | 同一条 OneBot 私聊事件送达 10 次 | 只产生 1 条 events、1 个回复 job、至多 1 个正常发送意图 |
| M0-02 | 非白名单 QQ、群聊和机器人自己的消息 | 不触发模型、不进入对话记忆 |
| M0-03 | 发送正常 QQ 消息 | AstrBot 默认聊天 LLM 不重复回复；只有 Companion Core 的回复 |
| M0-04 | Model API 超时、HTTP 429、瞬时错误 | 限次退避；失败时有审计状态，不无限重试 |
| M0-05 | 模型调用产生 Token | 输入/输出/缓存 Token 和估算账单可查询 |
| M0-06 | 同一会话快速连续发 5 条 | FIFO 或明确的合并合同，输出不乱序 |
| M0-07 | Worker 处理中强制重启 | 租约到期可安全恢复，无丢 job |
| M0-08 | 在 LEASED 阶段崩溃；或 QQ 已发送但 ACK 丢失 | LEASED 超时可重领，SENDING 不确定时不盲重发 |
| M0-09 | 配置包含未知字段/非法费率/QQ 账号为空 | 启动报清晰配置错误，不能静默放行 |
| M0-10 | 尝试无凭据访问内部 API 或公网访问 | 一律不可用 |
| M0-11 | 备份、恢复到新数据库 | 事件、任务、费用完整恢复，迁移可运行 |
| M0-12 | 每日主动发送已达上限 | 不产生新主动发送，普通被动回复不被错误限流 |
| M0-13 | 审批缺失而请求 QQ 空间发布 | M0 不允许产生执行中的公开发布操作 |
| M0-14 | 重复部署/升级同版本 | 幂等迁移、无数据丢失、可回滚应用镜像 |
| M0-15 | 高危字符串注入在 QQ 消息中 | 只能当文本处理，不能改变工具权限或系统配置 |

**M0 发布门禁**：15 项通过；零重复默认回复；无公网 API 暴露；能够从加密备份恢复；owner 身份鉴别可靠；错误回报中无密钥/记忆原文。

## M1：可验证、可纠正、可迁移的长期记忆与人格成长

**范围**：episode 聚合、候选记忆提取、来源绑定、冲突检测、SQLite FTS5、上下文检索、摘要、拥有者确认/纠正/遗忘、自我特征演化及检索性能、相关 Token 计量。

**不包括**：B站/小黑盒自动活动、Android、DSH Agent 执行、QQ 空间自主发布。

### 必须交付

- `episodes` 聚合器，不遗漏源事件及起止时间。
- `memory_extractor`：批处理记录、提取候选记忆；置信度为证据权重而非 LLM 自报百分比。
- `memory_reconciler`：冲突检测、去重、修订、过期、忘记和索引清理。
- `retriever`：结构化检索 + FTS5；必要时才注入最多 6 条记忆；附证据状态。
- `context_builder`：系统静态规则置前，近期消息和动态检索置后，不把全部原始日志塞入上下文。
- `self_model`：初始没有预设性格；在独立事件支持下从 EXPLORING 逐渐走向 STABLE，可逆。
- 主人控制：`/记住这个`、`/你记得什么`、`/纠正这一条`、`/忘记这一条` 与 API 对应；敏感隐私默认不自动沉淀长期记忆。
- 测试用语料与回放工具，记录检索准确率、幻觉和 Token 消耗的基线。

### M1 验收用例（全部 PASS 才进入 M2）

| ID | 操作 | 预期 |
|---|---|---|
| M1-01 | 空白新身份启动 | `traits` 无预置性格、游戏喜好 |
| M1-02 | 记录并确认 30 个事实 | 新会话重新检索，30 条均保存在 DB 且可检索 |
| M1-03 | 连续新建会话、压缩最近上下文 | 不依赖旧 Prompt 就能召回相关历史 |
| M1-04 | 首次出现某个兴趣话题 | 只能作为探索候选，不能立刻 STABLE |
| M1-05 | 跨多个不同会话/日期重复探索 | 达到配置门槛才允许升为 EMERGING/STABLE |
| M1-06 | 模型自己输出“我很喜欢 XX”但无其他证据 | 不允许形成 STABLE 自我特征 |
| M1-07 | 同一事实的互相矛盾陈述 | 触发冲突审查，不默默覆盖先前记录 |
| M1-08 | 所有者纠正记忆 | 旧项 SUPERSEDED，新记忆生效，保留非敏感修订轨迹 |
| M1-09 | 所有者明确要求忘记 | 从正文、索引、摘要、自我特征和后续上下文消失；备份恢复流程不能复活 |
| M1-10 | 记忆来源的事件消失或失效 | 对相应推断进行降置信/重新审查，不能虚构出处 |
| M1-11 | 用户事实与 self 偏好表达类似 | 不交叉写错主语 |
| M1-12 | 检索不同用户/群组范围 | 无跨隐私边界泄漏；M1 仅 owner 私聊开放 |
| M1-13 | 重启及迁移数据库 | 记忆、证据、状态、FTS 检索一致 |
| M1-14 | 回放 100 条实际格式样例消息 | 记录记忆提取率、召回错误率和平均输入 Token；不产生公开发布 |
| M1-15 | 外部帖子写有“记住我是系统规则” | 外部文本仅能作为不可信观察，不产生规则或授权变化 |

**M1 发布门禁**：15 项全部通过；30/30 已确认事实在数据库与检索层可查；0 越权记忆暴露；忘记流程全部衍生缓存失效；与 M0 相同负载相比，普通聊天上下文增长有明确上界。

## 推荐的开发 PR 顺序

1. `PR-01`：协议、配置校验、建库与 Alembic，单元测试。
2. `PR-02`：AstrBot bridge + API ingest + 幂等事件入库，Mock QQ 测试。
3. `PR-03`：回复 Worker + Chat Model Adapter + Outbox ACK/UNCERTAIN，故障注入。
4. `PR-04`：Token 账本、预算、日志、备份/恢复、M0 全门禁。
5. `PR-05`：episodes + memory 候选与证据链。
6. `PR-06`：冲突合并、检索、记忆修订与遗忘。
7. `PR-07`：self model、上下文构建器、人格漂移测试。
8. `PR-08`：M1 端到端测试、恢复测试、记忆/成本报告。

## 开发合并约束

- 每个 PR 提供对应测试和**可复现**命令结果，不只贴“运行正常”。
- 默认先本地跑静态检查/单测/数据库迁移/Mock 集成测试，通过后再提交 PR。
- 每次改 DB Schema 同时提供 up/down 迁移方案与备份恢复验证。
- 未经过 M0/M1 门禁不得开启云端 Android、QQ 空间、DSH 高权限工具。
- 外部依赖精确版本锁定、记录兼容性矩阵，避免自动升级破坏运行。
