# Conversation Policy 离线评测设计

**基准**：origin/main@72ff034（P0 任务，并行于 Bridge 延迟优化）  
**文档创建时间**：2026-10-28  
**状态**：设计草案

---

## 目标

在不依赖真实 QQ 或部署环境的情况下，用固定的上下文和问题集对比不同的 Conversation Policy 配置，量化"冷淡、敷衍、客服腔"问题的改善幅度。

## 评测维度

| 维度 | 检测内容 | 判定方式 |
|---|---|---|
| **冷淡** | 回复缺少情感连接、只有事实陈述、没有关心对方的语气 | 人工打分 + 自动关键词检测（"嗯"单独出现、"好的"不带后续、"可以"而无其他） |
| **敷衍** | 回复泛泛而谈、不针对具体问题、重复对方的话而不展开 | 人工打分 + 与用户输入的余弦相似度（过高表示复读） |
| **客服腔** | "请问"、"如有需要"、"很抱歉给您带来不便"、"祝您"等书面语 | 自动关键词/模式检测（正则） |
| **自然度** | 整体对话是否像朋友间聊天，而非机器人回复 | 人工打分 |

## 评测集设计

### 固定上下文

每个测试用例都包含：
- 最近 3 轮对话（用户和小肥鱼的往来）
- 用户的当前新输入
- 预期回复的性质（情感支持 / 信息回答 / 日常闲聊）

**示例场景**：
1. 用户抱怨工作累 → 期待情感支持，不要只回"辛苦了"
2. 用户问技术问题 → 期待具体回答，不要"您可以查看文档"
3. 用户分享喜悦 → 期待共鸣，不要冷漠的"恭喜"
4. 用户闲聊日常 → 期待自然接话，不要"请问还有什么可以帮到您"

### 测试集大小

至少 20 个场景，每个场景用 3 种不同的 Policy 配置各生成 1 次回复，共 60 条回复。

## Policy 配置对比

| 配置名 | 说明 | 调整点 |
|---|---|---|
| `baseline` | 当前线上使用的 Policy | 无调整 |
| `温度+0.1` | temperature 从当前值增加 0.1 | 增加随机性 |
| `提示词改写` | 在系统提示中明确"像朋友一样说话，不要客服腔" | 指令层面 |

## 自动评分脚本

```python
def score_response(user_input: str, response: str) -> dict:
    scores = {}
    
    # 1. 客服腔关键词检测
    service_patterns = [r"请问", r"如有", r"祝您", r"很抱歉", r"给您带来"]
    scores["service_tone"] = sum(1 for p in service_patterns if re.search(p, response))
    
    # 2. 冷淡检测
    cold_patterns = [r"^嗯$", r"^好的$", r"^可以$"]
    scores["coldness"] = sum(1 for p in cold_patterns if re.search(p, response))
    
    # 3. 敷衍检测（与用户输入的余弦相似度）
    user_emb = get_embedding(user_input)
    resp_emb = get_embedding(response)
    scores["repetition_similarity"] = cosine_similarity(user_emb, resp_emb)
    
    # 4. 回复长度（过短可能敷衍）
    scores["response_length"] = len(response)
    
    return scores
```

## 人工打分

每条回复由 2 名评分员各打分（1-5 分，5 分最好），取平均：
- **自然度**：是否像朋友聊天
- **情感连接**：是否让人感到被关心
- **针对性**：是否回应了用户的具体问题

## 输出报告

生成一个 Markdown 表格：

| 场景 | Policy | 自然度 | 情感连接 | 针对性 | 客服腔次数 | 冷淡次数 | 相似度 | 回复长度 |
|---|---|---|---|---|---|---|---|---|
| 1 | baseline | 2.5 | 2.0 | 3.0 | 2 | 1 | 0.85 | 8 |
| 1 | 温度+0.1 | 3.5 | 3.5 | 3.5 | 0 | 0 | 0.62 | 24 |
| 1 | 提示词改写 | 4.0 | 4.0 | 4.0 | 0 | 0 | 0.58 | 31 |

每个 Policy 配置的**总体得分** = (自然度 + 情感连接 + 针对性) / 3 - (客服腔次数 + 冷淡次数) * 0.5

## 实施步骤

1. 编写评测脚本 `scripts/eval_conversation_policy.py`，包含：
   - 测试场景定义
   - 自动评分函数
   - 批量生成回复的逻辑（调用 Core 的模型）
2. 生成 3 种配置下的回复，保存到 `.local/eval-conversation/`
3. 人工打分（或用 Claude 模拟评分员）
4. 生成对比报告
5. 选出最佳配置，再到真实 QQ 上验收
