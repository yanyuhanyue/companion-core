## 来源规则：主人确认的来源

在 `meme_trusted_sources` 之外新增一种规则，只能由主人确认后写入 Bridge 配置：

```toml
[[meme_owner_sources]]
name = "aigengtu"
index_url = "https://aigengtu.com/gallery-index.json"
index_sha256 = "<导入时的索引摘要>"
image_host = "img.aigengtu.com"
usage_basis = "仓库 README：个人聊天使用随意，商用请先联系原作者；仅主人私聊、非商用、不修改"
selection_sha256 = "<主人审过的选图清单摘要>"
```

审核器只接受同时满足以下条件的素材：

1. 编号在主人审过的选图清单里（清单固定为文件，摘要写入配置）；
2. 下载地址是 `https://<image_host>/meme/<编号>.<扩展名>`，单跳 200，不跟随重定向；
3. 字节通过现有 `validate_bytes`（格式、像素、单张 4 MiB）；
4. 记录来源证据：编号、原图 URL、字节 SHA-256、抓取时间、索引摘要和 usage_basis。

没有确认规则的站点照旧不收。下架请求到来时，按编号把素材停用，不再发送。

## 导入方式

复用现有后台发现任务（Core `meme_discovery` job + Bridge `MemeRuntime`），新增 provider
`owner_pack`：

- 每个任务从选图清单里取下一批（合同上限 8 张）未导入的编号，下载、审核、入库为
  「待识图」，再由现有 caption job 识图、建索引。
- 一次性导入期间调高 Core 的每日发现额度（查询次数和下载、存储字节），导入完成后改回。
- 识图请求把这张图的台词和使用场景作为参考文字一起给模型（标为不可信资料），
  让描述更准，不额外调用模型。

## 选图清单（先 500 张）

从 2339 张里按规则挑，生成清单给主人过目后再固定：

- 只要「梗图」类型（插画、漫画、立绘、设定图不适合聊天发送）；
- 按台词和使用场景分到现有意图：喜欢、调皮、晚安、安慰、庆祝、惊讶、早安。按关键词
  能直接对上的约 240 张；
- 剩下的名额给通用反应图（摆烂、委屈、嫌弃、得意、吃饭等），靠识图描述做语义检索；
- 跳过 GIF 以外的超大图和带明显他人肖像、政治或敏感内容的图；
- `meme_catalog_max_assets` 现为 512，500 张以内不用改。

## 识图费用

每张实际约 $0.0006（输入约 1024 token 图片估算加提示文字，输出约 200 token）。
500 张实际约 $0.3。需要改两处付费配置，属于付费合同变化，要走一次 C 类发布、
由主人批准新 policy：

- `meme_caption_max_output_tokens`：2000 → 600（减少每张预留）；
- `meme_caption_daily_micro_usd`：$0.05 → $0.50（导入期间），之后可改回。

按新预留每张约 $0.001，一天约 500 张以内，几天内可以导完。窗口总额 $7.50 内。

## 第二步：收藏主人发来的表情包

- 主人发的表情包（QQ 图片或动图）本来就会识图。新增收藏：主人说「这个存下来」，或机器人
  觉得合适时在回复里说明「我存了」，就把这张原图存入库，来源记为 `owner_shared`，
  证据为原 capture。主人的私聊消息就是授权依据。
- 撤回、删除原消息时，对应素材一起停用。

## 第三步：主人转发的帖子

主人发来小黑盒或 B 站帖子并明确说「把里面的表情包存下来」时，才读取帖子里的图片，
按第二步的方式入库。不自动批量抓取。

## 选图时机（可选，另行评审）

现在只有七类意图词触发候选，大部分对话不会带表情包。后续可以改为：每轮用当前文字做
语义检索，取相近度够高的少量候选给聊天模型自己决定用不用，频率仍受 35% 概率和
30 分钟冷却限制。这会让每条消息多一次本地检索（不花钱），需要单独评审。

## 不做

- 不自动抓 B 站评论区或小黑盒帖子里的图；
- 不修改原图、不加水印、不外传；
- 不使用 memecub 批量接口（商业站点，适合以后按需搜索少量图片）。
