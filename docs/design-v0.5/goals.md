# v0.5 目标、承诺、兴趣与有限唤醒

目标和主人承诺分开存储。目标可处于候选、等待来源、等待资源、队列、执行、有限重试、完成、失败或取消。每步有租约、尝试次数和隐私版本；重启恢复进度，过期进程不能提交结果。没有成功的观察记录、目标匹配和完整来源关系，不能标记 DONE。

主人通过 `安排任务 HTTPS链接 主题` 建立一项默认 24 小时期限的阅读承诺，或用独立 control token 的 `/internal/v2/commitments` 提交明确截止时间与主人请求事件。暂时的交互状态和“暂停自主活动”只影响自主探索；已接受承诺保留，达到期限会说明未完成原因。取消具体目标才结束相应承诺。

成功结果及失败说明复用 Outbox。`FULFILLED`/`EXPLAINED_FAILURE` 在反馈确认为 SENT 后才写入；发送不确定时等待主人核对，不盲目重发。恢复旧备份时，快照中的未完成发送统一进入 DELIVERY_UNCERTAIN，模型 RESERVED 计费转为 UNKNOWN 并保留金额，旧设备授权撤销。

`WakePlanner` 只产生有界的只读探索意图。时间槽或触发事件唯一、每日次数、冷却、免打扰、运行时暂停及费用已知检查都在事务内；无候选可以 SKIP，不调用模型。后续内容读取 Worker 消费已有目标步骤，唤醒器不执行高权限工具。

兴趣复用现有 `traits(category=interest)`。只依据已完成的自主阅读，主人任务和模型自述不计入；独立内容摘要、不同来源地址及多个自然日共同决定从 EXPLORING 到 EMERGING/STABLE 的变化。主人偏好仍属于 user Memory。来源删除清理目标、结果、承诺副本、兴趣证据和旧备份恢复路径。

夜间反思的待探索问题可以生成候选目标，仍需实际来源和可读目标才能推进。达到活跃目标容量时夜间整合记录 PARTIAL，并复用已经完成的日记与反思。

新增 QQ 指令：`目标列表`、`承诺列表`、`接受目标 ID`、`取消目标 ID`、`反思列表`、`当前交互状态`、`为什么形成偏好`、`暂停自主活动`、`恢复自主活动`。这些管理往返不重新进入记忆抽取或日记素材。HTTP v2 管理入口要求独立 control token，Bridge token 无管理权限。

`goals_enabled`、`wake_enabled` 和内容探索默认关闭。纯目标/唤醒决策不调用 LLM；实际读取另有请求、字节和次数配额。当前通过可控观察回放验证目标与发送协议，实际内容读取在后续增量中接入。
