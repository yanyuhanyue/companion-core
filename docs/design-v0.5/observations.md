# v0.5 统一经历事件

QQ v1 继续只接受主人私聊。新增 `/internal/v2/observations/{adapter_id}` 接收 `ObservationEvent` v2，按配置的独立适配器 token 认证并绑定来源。Bridge token 与其他适配器 token 不能写这个入口。`GET .../{adapter_id}/context` 只返回当前隐私版本，供适配器在外部读取之前捕获；提交时版本改变即拒绝。

`DISCOVERED` 只能包含标题；`FETCHED` 表示得到文字、图片分析或转写，不能声称看完视频；`WATCHED` 需要允许媒体分析的适配器、处理器版本、媒体摘要、分析时间段和完整覆盖证据。失败和未知结果不能携带成功观察正文。实际外部抓取和设备处理分别由后续适配器提供，校验器不能证明持有 token 的适配器本身没有造假，因此这些凭据仅交给受控适配器进程。

正文、摘要和 URL 均视为数据，事件入库不会调用模型、创建聊天任务、发 QQ 或执行工具。模拟来源仅允许 demo 模式。媒体原件只允许 discard；相机、语音和 Android 来源还要匹配主人授予的设备、会话、能力及到期时间。撤销会推进隐私版本；恢复备份会撤销所有旧设备会话。

管理接口使用独立 `COMPANION_CONTROL_TOKEN`：列出观察、遗忘观察、创建和撤销短期设备授权。开启全局能力开关本身不构成设备会话授权。摄像头、语音和 Android 默认关闭。

迁移 `0005_observations` 新增观察、事件依赖和授权表。外部 v2 信封规范化到已有事件存储；底层事件行继续使用 v1 数据库结构，避免重建现有聊天表。派生事件只可引用未删除的主人事实或已验证观察，日记命令不能成为事实来源。删除源事件时沿依赖图清理全部后代、索引和相关记忆，并通过同一独立 ErasureLedger 在旧备份恢复时重放。存在观察或授权数据时拒绝破坏性降级。

`tests/test_observations.py` 验证默认关闭、独立鉴权、来源级别、伪造证据、并发重放、提示注入无执行效果、传递删除、旧备份恢复，以及授权过期/撤销/设备不匹配。测试里的媒体分析证据是合成夹具，不能当作真实摄像头或视频客户端验收。
