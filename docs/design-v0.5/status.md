# v0.5 实现与启用记录

v0.5 在原有私聊、长期记忆和私人日记基础上增量实现。Core 保持唯一长期身份和数据所有者，AstrBot 仅负责传输与内容来源适配，模型适配器不持有存储或投递责任。

| 能力 | 当前代码路径 | 启用前所需条件 |
|---|---|---|
| 记忆 | 原有事实确认、语义召回、冲突与遗忘；新观察保留可追溯来源 | 现有模型配置与中文嵌入缓存 |
| 短期表达状态 | `affect.py`，真实反馈触发、TTL 衰减 | 显式开关；不会改权限或承诺 |
| 有限唤醒 | `wake.py`，时间窗口、冷却、预算与幂等决策 | 生活 Worker 与自主活动额度 |
| 感官 | `observation.py`、`content.py`、`media.py` | 各自来源身份、模型额度和必要会话授权 |
| 表达 | `expression.py`，文字与可选本地表情；复用 Outbox | Bridge 表情库与开关；语音目前通过媒体会话 |
| 夜间整合 | `consolidation.py`，复用记忆与日记任务 | 生活 Worker；日记与反思各自额度 |
| 兴趣与目标 | `interest.py`、`goals.py`，独立行为证据与持久任务 | 有效来源；明确接受主人承诺 |
| 反思 | `reflection.py`，有限候选与人工决策 | 独立反思预算；候选不直接改人格 |
| 执行控制 | `executive.py`，固定能力、精确审批、未知结果与预算保留 | 独立执行器、专用工作目录与短期审批 |

M2 内容理解优先承接主人发来的小黑盒/B站链接、QQ 卡片和图片。读取结果有原始链接、实际级别和证据；聊天优先引用当前内容。正文读取失败、只获得标题、图片分析未知时，均不编造已看过内容。现阶段没有完整视频理解或评论互动。

## 实际验证范围

自动化验证使用独立临时数据库、模拟模型/提供商及真实本地文件/HTTP进程。测试覆盖来源与权限、预算预留、隐私竞争、过期租约、重复请求、精确审批及加密恢复；模拟结果不会记作真实平台或设备验收。

真实 QQ 接管与至少20条私聊、20个真实匿名化日记日期的主人审核、真实平台账号读取、媒体提供商和物理设备均需按实际配置完成。历史 DeepSeek 合成记忆/日记报告仍为合成场景，不代替这些门禁。

Android 预检已确认目标 VPS 具备 KVM，但未确认可用 Binder/binderfs，也没有就绪 ADB 设备。因此当前交付预检与独立 Android 节点采集接口，未在现有 QQ 服务器安装或启动 redroid。

浏览器媒体会话使用有界 HTTP 分块采集与处理。WebRTC/P2P、QQ 原生通话和公开评论/空间发布仍在后续独立实验范围，默认没有执行入口。

## 启用顺序

1. 先在独立开发数据目录验证迁移、恢复、离线嵌入加载与进程存活。
2. 配置只读来源与 M2，逐项验证主人分享的内容范围和错误反馈。
3. 经真实 QQ 与日记样本核对后，分别启用短期状态、夜间整合及低频自主活动。
4. 工具和媒体另行配置独立凭据、预算与授权；每个模块保留关闭入口。
